# UI 测试与视觉验收

把用户指出的现象变成能复现的动作、能断言的结果和实际看过的截图。适用于本项目；从仓库根运行下述命令，技能资源路径均相对本目录。

## 开始前

- 先读 `docs/README.md` 对应功能入口与功能文档，再看代码；测试分工以 `docs/features/testing.md` 为准，视觉 token/字体以根 `design.md` 为准。涉及开合/切换时读 `docs/features/animation-system.md`。
- `git status --short` 确认已有修改。记录自己要改的文件；测试范围按本次文件清单或指定 spec，避免把其他人的未提交工作纳入本次验证。
- 写下当前问题的触发步骤与可见预期。例如「输入 `1. xxxx` → Shift+Enter → 输入框出现 `2. ` → 发送保留换行」。不要将「发送后能显示列表」当作「输入时能预览列表」的验收。

## 选择验证层

| 需要确认什么 | 选用什么 | 能证明的范围 |
|---|---|---|
| 数据转换、字符串、顺序、序列化 | `test/*.mjs` / 现有纯函数用例 | 输入与输出，不证明浏览器绘制 |
| React 状态、事件、队列、键盘、卸载 | `test/unit/*.spec.tsx` + 现有 API mock | 组件接线；jsdom 不证明排版和原生 contenteditable |
| 真实输入、光标、undo、CSS、字体、覆盖层 | 生产组件 + Chromium 夹具 | 真实浏览器行为；mock IPC 不证明主进程/原生窗口 |
| IPC、全应用层级、窗口/侧栏联动、原生视图 | 指定 Electron E2E / 聚焦的真 app 操作 | 对应 app 链路；需当前构建产物 |

选择能覆盖风险的最小组合。交互 bug 要有组件回归；原生编辑、层叠/模糊、几何和字体问题再补真实浏览器证据。只改文案/token 时，可按仓库规约豁免组件行为测试。

## 执行与查看

1. **先复现，再修改。** 使用真实入口；若难以稳定触发，先把失败现象固定到测试/夹具。截图与 DOM 原文、序列化值、回调/IPC 参数结合定位，不要只凭像素猜数据链路。
2. **补行为回归。** 用实际 `click`、`press`、`pressSequentially`、鼠标拖动触发。`innerHTML`/合成事件可以覆盖某种 DOM 形状，但应标明模拟范围；原生输入 bug 还要真实键盘测试。细节见 [references/regression.md](references/regression.md)。
3. **截图关键状态。** 使用当前生产组件和 CSS，不复制一个「看起来类似」的产品 UI。纯 CSS 最小夹具只证明该 CSS 条件；需要装配层级时升级为真实父组件或 Electron。脚本与实例见 [references/capture.md](references/capture.md)。
4. **打开图片查看。** 通过当前环境的本地图片查看工具逐张看相关截图（本环境为 `view_image`），先整图再必要的局部。检查用户指出位置、选中态、正文/辅助字、边距、裁切、换行、覆盖与重影。生成 PNG 或检查 CSS 数值都不能替代看图；无法查看时明确留下视觉验收未完成。
5. **收口。** 修正发现的问题，重跑相关失败项；达到预期且受影响测试通过就停止追加可选测试。同步功能文档与 journal。存在提交授权时，只暂存本次内容，正常提交让门禁验证暂存快照；不要跳过门禁。

## 选择状态，不机械铺矩阵

- 主题/材质/可读性：深色 + 浅色；涉及主题色时再选一个启用工作区色的状态。
- 响应式/输入栏：常用宽度 + 真实窄容器。组件起步可用 780/390px，整 app 用实际窗口尺寸；容器查询看容器宽度，不能只看 viewport。
- 输入区：空 → 输入 → 换行 → 清空，发送/排队/取回编辑按改动选择；看首字是否额外抬高、是否横向溢出。
- 开合/动画：展开/折叠/悬浮、连续切换与中途反转；稳定态截图可以禁动画，动画验收要保留动画并覆盖中间态。
- 层叠/拖动：截图包含背景文字和覆盖层；改变下面的活内容，确认固定快照没有透出第二套文字。不要以 `z-index` 数字代替绘制结果。

## 可复用入口

```powershell
# 单文件组件回归（换成此次相关的 spec）
npx vitest run test/unit/composer-live-markdown.spec.tsx

# 本技能：真实 Composer 组件、真实键盘、多状态截图、字体/几何/错误清单
node .agents/skills/ui-verification/scripts/capture-component.mjs
```

第二条默认运行随附的 Composer 示例，产物在 `.tmp/ui-captures/`；它是复用示例，不是全 app 或全部 UI 问题的验收。替换 `--fixture` / `--scenario` 验证本次组件，详见截图参考。

## 交付说明

最终说明：改了什么、真实触发动作与结果、跑过的测试/类型检查、实际看过的截图路径、模拟边界或剩余问题，以及有提交时的 SHA。截图用绝对路径链接；截图可能含真实会话，保持本地，不自动上传。测试通过和视觉验收分别报告；不把没有截图或没有看的状态写成已通过。
