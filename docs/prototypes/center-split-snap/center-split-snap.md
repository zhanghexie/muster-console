# Windows 分屏方式原型

用户在 2026-10-08 提供 `20261008094006_rec_.mp4`，要求转为录屏中的 Windows 分屏交互，先出原型。本稿用于评审新的交互方向，尚未替换正式分屏代码。

## 录屏与工作台适配

录屏中的窗口被完整提起，顶部出现布局选择条；指向一个小格后，桌面显示对应位置和大小的磨砂落点，源窗口仍是清晰浮窗，松手才落位。该路径取代上一版「边缘阈值内两块实际内容提前调整到最终尺寸并同时模糊」的原型方向。

原型把桌面范围换成中央工作面，保留默认隐藏的居中三点把手。工作台没有桌面上的任意应用窗口，因此空格提供未占用会话供用户逐格填入；这是工作台适配，录屏没有展示完整的空位选择流程。四个示例会话均为虚构内容，发送仅在原型中展示。

## 交互

- 点击三点打开菜单；按下即启用透明捕获层，移动 6px 才把同一个会话 DOM 整块提起。剩余只有一块时先铺满；草稿与滚动实例保留。
- 拖到工作面顶部 28px 内展开布局条。提供左右、左宽右窄、上下、主辅三格、并排三格、四宫格。实际小格命中依指针坐标，移动到布局条后保持展开，格子间隙清空候选。
- 候选只是一块按最终位置和尺寸显示的 16px 高斯磨砂区域。源会话缩成清晰浮窗继续跟随指针，背景会话不会提前停靠。预览不写入已提交布局。
- 左右边缘 18px 内也能半屏停靠，角落可选四分之一。大磨砂区域自身不是放置目标。松手按当时坐标重新命中；无目标、Esc、失焦、取消捕获或无主键的回移都恢复。
- 落位后只把源会话放入选定格，其他格逐一选择会话；已占用会话不重复出现。收起后只剩一个会话则恢复满幅；多格收起保留可填空位。
- 菜单支持 Enter/Space、方向键、Home/End，选择布局后焦点进入布局条，Esc 回原把手。侧栏导航关闭旧菜单与候选，离开布局条清空菜单路径的候选。
- 工作面小于 480px 时显示当前会话满幅，通过底部切换会话，不启用拖动。空位经「填入空位」展开小浮层，默认不会盖住正文。触屏布局条改为两列，格子有效尺寸至少 44×44px。

动画使用生产 `usePresence` / `usePresenceValue` 与 `base.css` 时长、曲线 token，仅过渡 opacity/transform。关闭时冻结菜单位置、落点和窄屏候选内容，退场层不拦操作。

## 验证与边界

51 个定向组件用例通过；覆盖全部布局小格、坐标命中与保持区、松手重算、取消出口、菜单与焦点、DOM/草稿、去重和窄屏填空。测试类型检查通过。

真实 Chromium 深浅主题检查了原生拖动、保持浮窗与全幅背景、精确落点/提交尺寸、候选间隙与无效释放、Esc、逐槽填空和实例保留。候选区域模糊/清晰边缘能量比为 0.019 / 0.017，确认实际高斯模糊；检查 620px 中间窗口与 320px 无横向溢出，触屏全部小格至少 44×44px。证据在 `.tmp/ui-captures/center-split-snap/`（截图与 `manifest.json`），已查看深浅预览、填空、四格和窄屏画面。

对话 iframe 外松手可能不向子页面发送结束事件；返回时发现主键已释放即取消，不猜测松手落点。当前真实 iframe 回归通过。本稿尚未覆盖正式 Electron、IPC、真实会话、终端/iframe 叶内容、窗口外拖动或多格生产模型，也没有提交、打包或安装。
