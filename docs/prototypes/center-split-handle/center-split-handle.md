# 分屏顶部把手原型

用户希望顶栏尽可能简洁，只留居中的三个点、渐变透明背景，点击出菜单，按住拖动整块面板。拖起一侧时，另一侧先铺满；达到边缘分屏阈值后，两块真实会话直接占据候选分屏位置，并一起高斯模糊。拖离边缘后恢复源面板清晰浮起、另一侧全屏模糊。本原型用于评价这一形态与操作手感，生产分屏逻辑保持不变。

## 推荐形态

- 每块内容默认没有可见顶栏，正文使用完整空间。
- 指针进入顶部小范围，居中的三个点显现，背后是一小片渐隐背景；不画标题、按钮框、底边线。
- 会话名称在菜单显示，正文顶部不增加标题栏。
- 按下把手后，移动达到6px才进入拖动；普通点击打开菜单，拖动结束不再触发菜单。
- 键盘聚焦、菜单打开和拖动期间保持把手可见；键盘可以访问菜单，Esc可以取消。
- 触控设备上的把手保持可发现，使用足够的触摸命中范围。

## 本地交互

达到6px拖动阈值后，源面板连同正文和输入框整体浮起，缩成便于携带的面板，跟随指针移动；未碰边界时抓取点对应原把手位置，碰到工作面边界时浮窗停在可见范围内，避免只剩把手。停靠仍按真实鼠标位置判定。剩余面板立即使用整个工作面。整页高斯模糊覆盖底层，浮起的源面板显示在遮罩上，保持清晰。

四边是停靠触发区域：进入左/右边缘时，两块真实会话按候选顺序直接左右分屏；进入上/下边缘时直接上下分屏。两块面板的外层、正文与输入框均使用候选最终矩形，尺寸与松手提交后相同；源面板取消浮窗缩放和高层级。两个高斯模糊区域分别按对应面板矩形裁剪，实际1px分隔线位于最终落位的分界处，让两块内容的大小和位置可直接辨认。没有描边框、空槽或额外名称标签。拖回中央时，源面板重新清晰浮起，另一侧重新铺满；中央没有交换落点。

预览会改变真实面板的临时几何，但已提交的方向、顺序、比例不变；松手处于边缘区域才提交新布局。中央或无效区域松手、Esc、失焦或捕获异常都取消并立即恢复原布局，不等待装饰退场。只有模糊遮罩保留presence退场，退场期间释放命中并位于菜单下方。两块会话DOM和父容器保持挂载，源面板不克隆、草稿不迁移；跨越停靠阈值不释放原把手的指针捕获。取消后可立即开始下一次拖动。此处调整工作面内布局，不创建独立系统窗口。

对话预览运行在沙箱iframe内：指针完全移到框外时，父页面的松手事件无法直接送到子页面。原型在指针返回框内、发现主键已松开时自动取消，不读取父页面；工作面外但仍在预览框内松手可立即取消。这个边界不代表正式Electron窗口的捕获行为。

菜单可切换布局、交换、调整比例，以及收起一侧或保留此侧。单屏保留相同把手，可从菜单重新选择另一内容分屏。单屏拖边不复制会话。

会话与草稿随内容移动，两块会话DOM保持挂载；关闭分屏后撤销半屏几何。工作面宽度小于560px时只显示当前内容，同时保留切换入口，扩宽后恢复原方向和比例；窄屏不启用拖边停靠，仍可使用菜单。单屏与窄屏的拖动不会提交新分屏。

## 源码与生成

- [组件](center-split-handle.tsx)、[样式](center-split-handle.css)、[生成预览](center-split-handle.html)。
- 生成：`node scripts/build-center-split-handle.mjs`；加 `--serve` 可以启动仅本机访问的预览，`--port 51271` 可复用已打开页面的地址。服务每次读取最新生成结果，刷新即可查看本轮修改。
- 组件复用生产 `usePresence`；生成脚本从当前 `base.css` 抽取 motion token。顶部渐隐为静态CSS；拖动遮罩使用固定强度 `backdrop-filter: blur(var(--shp-drag-blur))`，默认12px，不动画模糊值或面板尺寸。无候选时使用全工作面模糊；停靠候选使用 `preview-blur-a`、`preview-blur-b` 两个区域，矩形与对应真实面板一致。`drag-scrim` 父层透明度固定为1，不使用 `mp-scrim`；每个模糊区域自身接入 `mp-scrim` 与 `presence.spread`，避免祖先透明度过渡导致实际模糊没有绘制。
- 对话内容为示例，输入与布局操作只作用于原型；没有会话执行、真实IPC、扩展iframe或配置写入。

## 验证

- 原型组件和视觉测试已从套件移除；正式产品使用 `test/unit/center-split-panel.spec.tsx` 与 `test/center-split-production-visual.mjs` 验证，不保证与原型场景逐项相同。
- 收起时菜单退场换文案与跳位置的问题，新增用例在修复前转红，冻结菜单快照后通过。
- 实际Chrome深浅主题检查通过：无停靠时源面板在模糊遮罩上浮起、另一侧铺满；进入四边后两个真实内容使用最终候选矩形，每片模糊单独裁剪，分界使用与正式落位一致的实际1px分隔线。面板、正文和输入框的预览尺寸均与提交后逐项一致。30张截图与几何记录在 `.tmp/ui-captures/split-handle-final-size/`；像素模糊/清晰边缘比为0.028–0.033，旧错版基线为0.818，能够区分真正模糊与仅有遮罩的效果。
- 已重载用户正在看的 `http://127.0.0.1:51271/` 并现场拖动会话A到右侧：预览两块面板及模糊子层均为392×580，模糊子层透明度为1，实际分隔线为1×580；松手后两块面板的矩形逐项完全一致，截图确认实际高斯模糊。此前的四边往返中央、pointer capture、提交/取消/退出中重拖、跨iframe遗漏松手返回取消、DOM/草稿、收起铺满、键盘/双击分隔条与320px无溢出检查仍作为交互边界证据；旧版描边空槽及全幅停靠遮罩截图只作历史记录，不代表当前效果。
- 历史原型视觉测试曾在深浅主题检查快速拖动、预览几何及模糊像素；复原旧父层透明度动画时像素比0.833并触发失败。截图及记录在 `.tmp/ui-captures/center-split-handle-visual/`，原型测试脚本已移除。
- 验证对象是原型的React组件及浏览器预览，没有生产Electron会话、终端、扩展或IPC验收，不代表生产分屏已修复，也没有GPU性能验收。
- 诊断捕获到跨iframe松手缺失：父页面收到pointerup，子页面保持capture且没有up/lostcapture/blur；新增未按下pointermove取消回归在修复前转红，窗口级兜底后通过。没有通过定时猜测或父DOM读取掩盖边界。
- 对话预览只保存布局选择，不保存输入草稿；渐隐背景范围、强度和拖动模糊强度可通过预览调节入口调整。离线预览不依赖该入口。
