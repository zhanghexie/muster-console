# 任务与工作区简洁原型

状态：用户已确认原型，简洁布局已实现到产品组件；下拉菜单使用项目 CustomSelect，箭头内边距已调整。实现与验证边界见 [工作区管理](../../features/workspaces.md)，原型保留作设计参考。

## 展示

`task-workspace-simplification.html` 是 Codex 可视化片段，包含「编辑工作区」「新建任务」两页，通过顶部页签切换。外观跟随系统深浅主题。

## 设计取舍

- 工作区名称与头像合为一组，头像选项按需打开。
- 源文件夹首屏只显示完整路径和默认标记，长路径自然换行。点击一项后展开默认目录与移除；同一时间展开一项。按用户反馈取消排序及显示名称编辑，展开区不再重复路径。管理目录的移除保护仍可见。
- 索引及范围、隔离准备命令、关闭工作区集中到更多设置。准备命令保留独立保存入口。
- 新建任务优先呈现任务内容、源目录、运行方式和隔离开关；运行位置直接使用完整路径，并使用整行选择控件容纳路径。隔离范围以摘要呈现，点击后选择仓库及运行仓库。
- 会话名称放在标题下方、任务输入框上方；运行方式与会话模式并排，模型与思考强度并排，所有会话字段直接显示，窄屏自动堆叠。「新建空白」与「开始任务」放在底部同一个按钮组，任务为空时仍可新建空白。新建任务页已完全去掉更多选项。名称留空仍自动命名，选择 CLI 时按现有能力边界隐藏 GUI 专属模型参数。预览默认打开新建任务页。
- 按用户反馈，启用隔离时默认选中工作区内全部可隔离仓库，摘要显示「全部仓库」，用户可展开调整范围；重新启用隔离也恢复全选。父仓包含子仓的语义保留，取消对子仓的显式选择后若仍被父仓包含，会显示「随主仓库隔离」。正式实现需把全选规则用于实际仓库发现结果，并保留错误及来源校验。

## 验证及边界

- 原型组件回归 spec（task-workspace-prototype.spec.ts，原 14 项直接执行原型 DOM 和事件代码）已于 2026-10-10 测试清理移除：设计已落地生产，行为由 test/unit/task-workspace-simplification.spec.tsx 等价覆盖。
- 真实 Chromium 内预览并查看深色两页首屏、浅色 390px 文件夹展开和隔离范围；检查无横向溢出，并用真实输入及 Ctrl+Enter 触发任务演示。
- 本次反馈调整后再次查看文件夹展开及隔离范围：排序按钮已消失，默认两项仓库都显式勾选，摘要显示「全部仓库」。
- 路径显示调整后，320px 实际浏览器检查列表收起/展开及新建任务运行位置：列表路径换行，无横向溢出；展开操作中没有显示名称输入，也不重复路径。
- 最新 736px 及 320px 实际浏览器检查：会话名称位于任务输入框上方，会话模式在常规宽度与运行方式并排，窄屏自动堆叠；会话字段直接可见，新建任务页没有更多选项。「新建空白」与「开始任务」保持相邻，无横向溢出；前轮实际点击新建空白，在未填任务时显示空会话准备成功的原型反馈。
- 保存、任务创建、仓库刷新、准备命令均为本地演示，没有 IPC、磁盘操作或真实任务执行。模型菜单用「跟随 Codex 配置」及「示例模型」演示，未读取实际模型目录；正式实现应继续由运行时真实目录及参数描述提供选择。添加文件夹用输入路径模拟原生选择器；图片上传仅反馈所选文件名。索引开关/范围只演示选择，不验证建索引。
- 原型使用瞬时开合，不作产品动画验收。确认设计后，产品组件的进出场须继续接入既有 usePresence/motion 体系，同时保留错误、依赖守卫、异步加载、队列及取消状态。
