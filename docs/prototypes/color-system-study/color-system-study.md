# 配色系统设计稿

状态：2026-10-09 独立 soft / clear 稿均被用户否定，仅保留历史记录，不算视觉验收。当前方向是生产原材质下的真实 Electron 组件/runtime“原版 / 局部微调”同场对照，生产配色未迁移，最终 token 数值待确认。对应 全审报告 与 顶层规则/迁移清单。

## 历史独立稿范围

- 工作台：内容标签、第二行当前工具、右资源树、文件/Git/浏览器切换、终端分屏、会话/调度胶囊、ghost 收起、双方中性头像、输入顶沿。
- 设置：12 个真实导航入口，重点展示外观、共用设置行/字段与状态；其他入口是呈现模板，业务字段不作为产品实现。
- 组件状态：行/按钮/输入/focus、Badge/Alert/进度、菜单/确认弹窗、看板/记忆/统计/手机代表面。
- 规则与覆盖：同源色阶、实际正文/辅助对比数值、完整 UI 迁移领域。

顶栏切换深浅、主题色关闭以及玫瑰/蓝色/青绿/琥珀。主题色轻染宿主全部表面；默认头像不随项目色改变。通过一份 palette 输出具体色值，不在组件内各自叠 tint。原生 Mica 在这里使用实色框表达层差，非原生材质验收。

该稿以项目 TSX/CSS 建立可检查的 UI，复用现有 icons 和 usePresence。它是设计模板，不是生产组件快照；普通网页、终端输出也为本地 fixture，不能据此声称真实网页、xterm 或 IPC 已修好。浏览器稿使用系统字栈，正式字体应在真实应用迁移时验证。

## 用户反馈与当前对照方向

用户认为首稿整体灰蒙、对比不足。首稿的问题包含两条独立轴：内容底被整体抬亮，相邻内容/工具/选中面过近；又为最亮选中面校准文字，把普通面的辅助文字也推亮。文字对比达标只能证明能读，不能证明标签、当前工具和内容层级已经清楚。

用户再次拒绝 clear 观感，并指出原型可能失真、配色改动过大。soft 和 clear 都已被否定，不再把整套 clear 色阶作为默认提案。clear 的深色 #14171c / #252a33 / #282f3a / #3e4b5f、浅色 #ffffff / #e5eaf1 / #c1cedf，以及内容 1.2% / 工具 2.5% / 框 12% 轻染仅属于历史原型记录，不是实施合同。

当前对照改用 `scripts/capture-color-system-native.mjs` 和 `docs/prototypes/color-system-native/color-system-native.css`，在真实 Electron 构建组件/runtime 做局部样式微调。保留生产基础色、字体、布局与原材质：背景种子 #141416 / #202023、原生框 28% 覆盖、sheet 18% 混色、input 8% 混色先不重设，以便同场比较原版与局部变化。范围先集中于标签/工具/内容同源、身份/状态一致；主系统审计、全 UI 覆盖矩阵和跨渲染器同源目标继续保留。

普通/选中表面独立配对仍是设计原则，但 clear 稿文字与表面明度检查不能代替视觉确认。其 chrome / canvas 深 1.2、浅 1.15，以及 selected / chrome 深 1.5、浅 1.2 的表面阈值不作为后续实施合同，也不是无障碍通用阈值。最终 token、文字配对目标与表面层差在原材质的真实组件同场对照确认后锁定。

本轮桌面采证被 Windows 搜索浮层遮挡，相关截图已弃用；正在改为后台 capturePage 加实色回退框。它能查看真实组件绘制，但不能据此验收真实 Mica。下面数字是历史独立稿的机械验证记录，不代表用户认可、当前对照已经通过或生产修复。

## 历史独立稿运行与验证

```powershell
node scripts/build-color-system-study.mjs --serve
# http://127.0.0.1:47841
node scripts/check-color-system-study.mjs
```

`--visual-copy <绝对路径>` 可同步当前会话的设计稿副本；源文件 `color-system-study.tsx/.css`，HTML 由构建脚本生成。motion token 从 base.css读取；浮层使用 usePresence，截图等待实际 transition 完成。

历史上 9 项原型组件测试通过（脚本现已移除）；20 个明暗/项目色/版本组合校验普通面主/次/辅助前景≥7/5.5/4.5，选中面独立前景达到同一目标，强调按钮与身份配对验证。新增表面层级检查及版本切换保留输入回归。tsconfig.test 类型检查通过。21 项真实 Chromium 检查通过，结果 `output/playwright/color-system-study/verification.json`。12 张最终截图均已打开查看：初稿/清晰版对照、深浅/玫瑰/蓝色、文件/Git/网页/终端、设置、组件/弹窗、390px窄稿；另有1024/736/320几何检查。最终菜单/弹窗为实底，四边焦点和顶沿连续，无整页横向溢出。实际玫瑰配色的工具/内容表面对比深色1.274、浅色1.220，选中/工具深色1.616、浅色1.321；这些是层级设计指标，不是文字可读性比值。

首轮发现选中面/染色框的辅助文字不足4.5，曾通过共同文字配对校准修正；用户随后指出整体灰蒙，clear 修订又采用普通/选中分别配对并提高表面层差，但仍被用户否定。修订时还发现按比例向白色校准会因 hex 取整停滞，改为单通道步进并通过20组配对检查。以上证据仅对应被否定的独立设计稿，不覆盖当前真实组件对照、安装版或全部生产页面，也不代表视觉验收。
