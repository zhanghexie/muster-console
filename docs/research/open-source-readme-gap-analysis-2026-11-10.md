# 开源 README 差距分析（2026-11-10）

## 结论

当前仓库的产品能力已经比首页表达出来的多，但原 README 把用户入口、内部实现说明、测试规约和宿主协议边界混在一起，读者需要先读完大量中文技术清单，才能回答三个最基本的问题：

1. Muster Console 是给谁用的？
2. 五分钟内怎样跑起来？
3. 它和单个 coding agent、IDE 或终端的关系是什么？

热门开源项目的 README 通常把这三个问题放在最前面，再用截图、安装路径、功能链接和社区入口把信任建立起来。Muster Console 的特色不是功能数量不够，而是这些特色没有以公开用户能快速扫描的方式出现。

本次已完成的落地：

- 根 README 改为英文用户入口，顶部提供 [简体中文镜像](../../README.zh-CN.md)。
- 保留原有中文技术内容到 [README.zh-CN.md](../../README.zh-CN.md)，避免丢失现有内部知识。
- 暂不在 README 中引用图片，等后续重新采集与审核后再补充。
- 为编排、Worker、看板、Git、浏览器、扩展和记忆补充源码与功能文档链接。
- 新增 [CONTRIBUTING.md](../../CONTRIBUTING.md)，把贡献者需要的验证和文档规则从 README 中移出。
- 明确当前没有 LICENSE、公开安全联系入口和完整三平台发布验收，避免给新用户错误承诺。

## 差距矩阵

| 维度 | 原 README 的状态 | 对用户的影响 | 处理方式 |
| --- | --- | --- | --- |
| 首屏定位 | 中文宣传语后直接进入内部定位和实现清单 | 新用户难以判断产品是否适合自己的工作流 | 新 README 先说明“调度 Agent + 多 Worker + 工作台”模型，并解释与单个 agent 的关系 |
| 语言 | 几乎全部中文，代码名和用户文案混排 | 国际用户无法完成首次阅读；中文用户也缺少明确语言入口 | README.md 英文；README.zh-CN.md 保留完整中文镜像；两者互链 |
| 首次启动 | 有开发命令，但缺少“先装什么、第一次打开做什么、哪些命令是安全沙箱” | 安装后容易停在空白配置页 | 增加 Requirements、Install and run、首次设置和 sandbox 说明 |
| 特色表达 | 功能很多，但以内部模块清单为主 | 看不出调度、真实执行、隔离验收、跨工作区看板的组合价值 | 以六组能力介绍特色，每组都附 feature 文档和源码入口 |
| 视觉证据 | 旧 website 和截图素材已过时 | 继续引用旧图会把旧版本体验误传给新用户 | 本次删除旧 website 和 README 图片；后续使用新版本截图重新补充 |
| 代码可追溯性 | 结构树存在，但关键能力和源码入口没有一一对应 | 开发者无法从产品概念快速跳到实现 | 增加 How the pieces fit、Code map 和每个能力的源码链接 |
| 安装路径 | 只覆盖源码开发命令 | 真实用户找不到发布包、平台状态和限制 | 增加三平台构建命令、平台支持表和发布验证边界 |
| 文档分层 | README 承担了大量内部协议、测试和配置细节 | 首页阅读成本高，内部约定会被误当成用户承诺 | 技术细节继续由 docs/features 承载；贡献流程转到 CONTRIBUTING |
| 开源信任 | 当前没有 LICENSE、CONTRIBUTING、公开安全入口 | 用户无法判断能否再分发，贡献者也没有入口 | 本次补 CONTRIBUTING；README 明确把 LICENSE、安全联系和 release artifacts 列为发布前工作 |
| 社区与版本信号 | 没有公开 issue、讨论区、下载、release 或 CI 信号 | 用户无法判断项目是否活跃、如何求助 | README 先保留诚实的 early access 状态；待仓库公开后补动态链接和 CI 徽章 |
| 平台承诺 | 产品描述面向三平台，但部分发布/权限链路仍有边界 | Windows 验证可能被误读为三平台验收 | 增加 Windows/macOS/Linux 分平台状态，并链接 packaging 说明 |
| 品牌一致性 | 旧 website 使用 MetaAgent 工作台和 .metaAgent 术语 | 旧站点和当前应用身份不一致 | 本次删除旧 website；后续只在新版本素材准备好后重新建立介绍页 |

## 语言与内容策略

README 的英文版本承担“产品首页”职责：

- 用一句话说明用户结果，而不是先解释目录结构。
- 首屏只保留能帮助决策的信息：对象、工作方式、核心差异、状态。
- 功能按用户能力分组，每组最多四个深入入口。
- 代码链接指向稳定的目录或入口文件，细节留给 docs/features。
- 安装路径按源代码、构建、平台和首次配置分开。
- 公开尚未准备好的部分用状态表声明，不用模糊的“支持全部平台”。

中文镜像保留当前已有的实现密度，适合团队内部查协议、运行时、配置和测试细节；它不再承担英文首页的阅读负担。贡献流程另放在 CONTRIBUTING.md，根 README 只保留入口和原则。

## 发布前优先级

### P0：没有这些就不要对外宣称“可直接使用”

1. 选择并提交 LICENSE，同时检查依赖许可证和第三方资源声明。
2. 发布至少一个可复现的 release artifact，写清版本、平台、校验和、已验证范围。
3. 配置公开 issue、漏洞报告入口和最基本的支持路径。
4. 对 README 中的 clone、安装包下载和仓库 URL 做一次公开仓库实测。
5. 后续重新制作介绍页和截图时，统一使用 Muster Console / .muster 身份。

### P1：显著降低首次流失

1. 加入 CI、typecheck 和最小冒烟测试徽章，徽章只引用真实 workflow。
2. 为三平台各写一页“安装后第一步”和已知限制。
3. 把截图中的关键流程拍成一段短 GIF 或视频：一句话派活 → Worker 执行 → 看板等待验收。
4. 给每个主打能力补一个可复制的最小任务示例，而不是只描述功能名。

### P2：形成社区增长回路

1. 发布 roadmap、变更记录和版本迁移说明。
2. 增加示例工作区或可下载 demo 数据，让用户不用先理解全部宿主协议。
3. 发布 extension/Skills/MCP 的贡献模板和安全边界示例。
