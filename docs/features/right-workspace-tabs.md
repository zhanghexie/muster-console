# 右侧统一多标签工作面

## 功能职责

右侧由左边内容工作面与右边资源树组成。文件、图片、网页、Git 仓库、独立 Diff、轮次审阅，以及从左栏 / 中栏固定过来的会话、终端、内置实用功能和扩展共用内容标签栏。用户从右侧资源树、收藏夹或全局搜索打开的标签默认在当前工作区内共享。会话内跳转或会话 AI 新建的资源标签只在所属会话显示，标题旁带对话图标，悬停显示「跟随会话」。从右侧内容继续开页时继承父标签的归属。

「固定标签页」将标签排在当前列表前部并保护它免于「关闭其他」「关闭右侧」和「关闭所有未固定」。固定和取消固定保留原有工作区或会话归属。标签、选择和文件根身份按工作区隔离。

渲染层的 `rightPanelState.ts` 可读取当前工作区已水合的可见标签、选择状态和文件编辑快照；`panel:snapshot-request` 内部桥还返回中央分屏与虚拟屏轴状态，主进程按调用者身份绑定工作区并验证响应来自目标渲染进程。文件、仓库和差异内容按调用者的实际可读目录及真实路径过滤；范围外或无法确认的内容标记 `redacted`，编辑器仍报告活跃和未保存状态但不返回文件路径。工作区不匹配、切换中、尚未就绪或多个表面存在歧义时明确失败。标签模型支持持久化明确指定的 `user` / `agent` 来源，复用已有标签不会改写来源；手动点击右侧文件树的入口记录 `user`，旧标签及尚未接线的入口标记 `unknown`。`catalog/hostPanel.ts` 提供公开 schema；`host.panel` 已注册，网页及其他不支持的中央放置会明确拒绝。

内部标签聚焦和关闭先按调用者范围读取并确认目标；范围外标签不可操作。主进程将已验证的内容身份随请求传回渲染层，渲染层在实际操作前再次比对，防止预览标签复用 ID 后误操作新内容。快照的 `deferredDock` 区分后台占位和已经移至右侧的视图；中央焦点允许仍在中栏的延迟占位，状态缺失时保守拒绝，渲染端提交前仍复核当前停靠状态。原有固定标签与未保存编辑保护仍生效。

内部面板桥与上传共享调用者范围：CLI 会话使用实际进程的冻结目录租约，进程换代或退出即拒绝旧请求；GUI 会话有当前回合范围时，回合换代也使旧请求失效。

内部打开桥支持文件、图片、已登记仓库、仓库文件差异、同工作区会话和四个通用实用工具；设置经专用桥准备并支持右侧标签。差异目标必须在所选仓库及调用者可读范围内，真实路径逃逸会被拒绝。相同内容复用已有标签，默认不更改当前标签。代理后台登记会话或工具时只创建延迟停靠标签，不移动中栏的唯一视图实例；显式选择后才停靠，延迟状态可跨重启恢复，关闭其他标签也不会隐式激活它。会话在主进程及渲染层分别检查工作区和归档状态，工具标题由宿主确定。用户固定到右侧的视图不得由代理关闭；用户后来固定代理标签也受到保护。关闭代理自己的未固定视图不终止会话进程。公开工具按 schema 提供对应内容类型，不支持的位置明确拒绝。

中栏文件视图仍在开发：`prepareAgentCenterFile` 在右侧实例管理器中准备一个不显示于右侧标签且不持久化的内部文件实例，重复准备复用已有实例；用户主动在右侧打开同一实例时沿用原 ID。后台请求不得悄悄把已在中栏的实例移动到右侧。释放内部实例需重新核对内容身份，拒绝仍有中栏宿主或未保存编辑的实例；已变成用户右侧标签的实例不由该接口移除。文件编辑器的宿主复用 DOM；对于已连接的 iframe 和媒体，如果没有 `moveBefore` 或安全移动失败则报错而不退回普通移动，已连接的 webview 一律拒绝移动，目标未连接时不摘除现有视图。内部中栏渲染与聚焦已接入，公开 `host.panel` 可调用该桥，未经预检的生命周期不能假定安全。安全分支有组件模拟，Windows Electron 验证了文件跨栏及右侧接回同一编辑器；其他平台尚未实机验证。

安全移动回读 DOM 父节点；目标未接住实例时不报告成功。移动到中栏失败时文件编辑器继续采用原右侧的可见与活动状态，并显示错误。`releaseDockTarget` 在调用者仍保留目标宿主时先确认单一来源和目标、将实例安全移回并回读父节点，再注销目标；失败时保留目标登记。中栏关闭和右侧接回使用该预检；工作区移除与窗口生命周期仍需验证，未经预检的 React 卸载不能声称已保护实例。

`beginDockReturn` 为多个宿主提供批量预检和可提交或回滚的归还事务：先验证全部来源和目标，事务期间排他保留这些宿主并暂停普通停靠移动；移动失败时将已移动的实例恢复，主操作失败可回滚，提交时再次检查宿主身份，恢复失败明确报告未知。`releaseDockTargets` 在同一调用中准备并提交。工作区关闭使用该事务，保存和关闭失败时回滚。

工作区关闭通过主进程 `closeWorkspaceCoordinated` 与渲染层握手：先冻结交互、依次 flush 文件并复核身份和未保存状态，再准备停靠归还事务；准备失败阻止关闭，关闭失败回滚。成功后先广播工作区状态并等待渲染层观察到删除，再提交归还和清理文件实例。并发切换、更新和代理移动在准备期间受保护。准备超时会解除界面冻结，迟到结果仍被回滚；若文件写入已经发出，其最终磁盘结果可能未知，应检查文件。关闭后清理失败会明确报错，不伪称工作区仍存在。普通跨工作区切换仍保留实例和草稿。Windows Electron 回归覆盖保存失败、超时和成功关闭；macOS、Linux 尚未真机验证。

从右侧文件树、标签或历史显式重新选中已在中栏宿主的文件时，先执行安全移回；失败则保留原实例并提示。关闭右侧标签时若文件仍被中栏宿主持有则拒绝，避免同时卸载另一个视图；代理选择还须通过未保存保护。Windows Electron 已验证从文件树接回同一编辑器 DOM；文件桥由 `host.panel.open` 使用。

Windows Electron 的内部桥用例也打开并实际解码一张中栏 PNG，检查图像可见和非零像素尺寸，再关闭其后台引用；这不覆盖所有图片格式或其他平台。

内部文件实例读取接口按当前工作区与会话范围查找，返回独立副本及 Pin、归属中栏状态；右侧模型变更会发出通知，供未来中栏桥重新核验内容身份。读取不到或存在多个管理器时不能猜测目标。

面板桥的 Windows Electron 用例覆盖深浅主题的常规窗口，以及测试夹具临时解除最小宽度后的 760 像素窄窗口，检查后台打开、去重、过期目标拒绝和抽屉切换；并排内容是终端会话，不代表 AI Worker 已验收。聚焦过程中偶发的可见性未知回执仍在排查。其他平台尚未实机验证。

内部 `panel:open-content-request` 在右侧后台登记文件、已登记 Git 仓库、仓库差异、同工作区会话或内置工具：主进程校验调用者可读范围及源根、仓库或会话身份，已有标签复用且不改写来源。Git/Diff 标签身份复用跨平台路径比较：Windows 忽略大小写，macOS/Linux 保留大小写。请求显式切换时，活动编辑器有未保存内容则拒绝；工作区切换、超时或应答无效后可能已经打开，回执标记结果未知并要求先检查。其余不支持的位置会明确拒绝。

内部 `panel:close-tab-request` 处理文件、图片、Git、差异及代理打开且未被用户固定的会话和工具标签。它先同步用户待处理的标签状态，再拒绝固定标签、工作区共享资源标签和含未保存内容的文件，最后只关闭对应视图。扩展等其他种类返回未实现。取消或丢失应答时结果可能未知，不能自动重放。

内部 `panel:focus-tab-request` 选中现有右侧标签，并在宽窗口切到右侧工作面、在窄窗口打开右侧抽屉；显式 `focus:true` 的打开请求使用同一流程。主进程回执等待切屏动画完成、右侧可见面积检查以及目标身份复核；活动文件有未保存内容时拒绝隐藏它，打开设置模态或显示未保存设置草稿时也不切走。工作区或目标在等待中变化、等待动画期间右侧页面离开视野、请求取消或无法确认可见性均返回未知结果，调用方应先检查。`panel:focus-axis-request` 在窄窗口同步打开或关闭右侧抽屉，等待相应页面可见后回执；中央焦点仅支持已经可见的分屏引用。

第一行的左右箭头分别执行「撤销」和「重做」，旁边是内容标签、Pin、页签管理、资源类型和收起按钮。悬浮提示显示可撤销或重做的步数与当前快捷键（默认 `Ctrl+Alt+←/→`）。第二行显示当前内容的位置和工具。文件显示完整路径与保存状态，并提供预览、编辑、保存、查找、复制路径和树定位。Git 显示仓库、分支、变更、历史、PR 及同步反馈。浏览器显示可编辑的完整地址，并提供刷新、收藏、复制网址、元素备注、DevTools 和系统浏览器入口。Git 同步反馈见 [Git 操作与同步反馈](git-operations.md)。

内容分栏在可容纳时至少保留 360px，资源树至少 160px；更窄宿主沿用 SplitPane 的比例压缩。第二行以内容分栏宽度响应，工具不足时可横向滚动。胶囊只切换资源树，不改变当前内容；切内容标签、历史回放或打开内容则让资源树跟随类型。收起状态在内容导航时保留，手动点击胶囊或树定位会展开。4px 调宽热区与可见线都在正文和资源树接缝的中心。网页显示时，热区跨在两栏共用的边缘，网页与资源树紧邻。线宽静息 1px，悬停和拖动 3px。顶栏不增加竖线。

标签关闭按钮在悬停、标签内聚焦或标签选中时以 opacity 显现，始终保留原有槽位；按压关闭和工具图标时只对内部 SVG 做微缩。反馈统一使用 `--dur-micro` / `--ease-hover`，快速反向自然续走并服从减少动态偏好。标签标题、按钮命中范围与布局几何保持，关闭仍阻止冒泡选中，键盘和中键操作沿原路径执行。

审阅标签的固定标题和无路径时的悬浮提示随界面语言切换；实际仓库、文件路径和用户提供的标签名称保持原样。

右页退到虚拟屏露条时，标签管理和资源树的右键菜单收起，审阅内容随右屏平移。切回后继续查看原来的审阅标签。

**标签多选（2026-10-27 起）**：内容标签条支持 Ctrl/⌘ 点选与 Shift+←→ 范围（横向轴，共享 `useListSelection`），Ctrl+A 全选、Esc 清空；修饰键点击不切换当前标签。右键落在多选区内时菜单新增「关闭选中的 N 个标签页」——显式选中的关闭不受 Pin 保护限制（与「关闭所有未固定」的批量保护语义区分）；关闭后选区清空。回归：`test/unit/right-tabs-multiselect.spec.tsx`。

工作面外壳使用 `overflow:clip`，不持有横向滚动位置；标签、工具、资源树和正文各自管理内部滚动。`overflow:hidden` 仍允许 Chromium 为聚焦控件滚动整个外壳，曾使 480px 窄屏抽屉内的网页向左偏移 59px；真实浏览器回归需同时断言完整 guest 边界位于抽屉内，不能只验证中心点可见或按钮能点击。

## 内容分屏

右侧内容标签栏的布局按钮与标签右键「选择分屏布局」打开与中央区共用的 Snap 选择器。也可拖动标签到预设格子，标签之间仍可拖动排序。支持左右、上下、三列均分和两种一大两小布局，最多同时显示三个标签。选择档位与落点后保留已显示的标签，剩余格子可以点选或拖入其他已打开标签。容量不足的预设不可选。拖动分隔条或用方向键调整比例，按 Esc 可取消本次拖动。

切到已显示的标签只更改焦点，选择其他标签会填入当前焦点格。每个分屏包含该标签自己的位置和内容工具栏，编辑、保存、查找与网页地址等控件作用于所在格。右侧资源树跟随焦点标签。每格「收起此侧」保留对应标签，余下两格按位置转为左右或上下，剩一格时回到单屏。标签菜单的「解散分屏（保留此侧）」直接回到当前标签。关闭标签沿用保存、关闭和撤销流程，分屏组合与比例在当前工作区和会话内保留，切换作用域或重启后从单屏开始。全屏期间只显示选中标签，退出后恢复分屏。

`useRightWorkspaceSplit.ts` 按可见标签 ID 管理槽位，复用 `shared/centerSplit.ts` 的预设和落点计算。右侧预览与中央区共用 `CenterSnapBar` 与 `SnapDividers`。编辑器、停靠视图、扩展和网页仍在原有宿主，槽位只改变几何和可见性。多个网页继续由唯一的 `BrowserPage` 管理，每个原生 guest 使用自己的槽位边界。宿主通过 `browser:guest-click` 报告真实 guest 点击，渲染层只聚焦当前右侧可见分屏中的匹配标签。

AI 通过 `host.panel.run` 的 `list` 读取 `snapshot.right.split` 和 `selectedTabId`。单屏时 `split` 为 `null`，分屏时返回预设、物理格位顺序和比例。用 `split` 加 `placement: "right"`、`layoutId` 和现有标签 ID 排布各格，传 `ratio` 或 `ratios` 可同时调整分隔线。已有选中标签在目标格位中时保留焦点。用 `focus` 的 `tabId` 切焦点，用 `close` 加右侧位置和格位索引收起单格。省略索引会保留当前标签并解散分屏，标签条保留原标签。

右侧布局 IPC 使用 `panel:right-layout-request`，主进程绑定调用者工作区、读取权限和涉及的标签身份。渲染层按当时的会话、格位、比例和内容身份提交，拒绝遮住有未保存编辑的格位、正在换区、全屏、拖动或不再可用的目标。成功分屏会确认右侧工作面实际显示。应用后的状态在应答前变化时返回 `unknown`，调用方先用 `list` 回读。

组件与主进程回归见 `test/unit/right-workspace-ui.spec.tsx` 和 `test/browser-tab-lifecycle.mjs`。macOS Electron 用 `test/e2e/right-workspace-split.spec.ts` 验证了独立工具栏、文件与两个网页同显、跨 guest 拖动分隔条，以及缩窄窗口后网页草稿与 guest 保活。同一用例还通过 `host.panel.run` 读回格位、唤出右侧、重排和调比例、聚焦、收起和解散。Windows 和 Linux 尚未对本次改动做真机验证。

## 标签页整屏显示

所有右侧内容标签的右键菜单提供「全屏显示」，先选中右键指向的标签，再使用 HTML Fullscreen API 占满当前显示器。网页、文件、图片、Git/Diff、审阅、停靠会话/工具和扩展共用入口；不移动编辑器、iframe 或 webview 的 DOM 父节点。全屏时临时隐藏左中工作面、资源树和第二行内容工具栏，第一行标签栏改为顶部 10px 热区唤出，移开或点击正文后淡出；沿用 `usePresence` / `mp-scrim`，退出按钮和同一标签的右键「退出全屏」均可恢复。

共享 `hooks/usePaneFullscreen.ts` 管理原生进入/退出、已有 document 全屏的保留、失败提示和迟到回执；中央分屏通过 `useCenterPaneFullscreen.ts` 适配同一机制。`SideToolsPanel` 仅对呈现增加 `is-tab-fullscreen`，不改写资源面板开合、分隔比例或虚拟屏偏好。全屏中直接点击标签、用键盘切换或通过右键选择其他标签全屏，都会跟随新标签继续显示，不重进原生全屏；切换时保留顶栏的当前悬停/键盘显示状态。关闭当前标签后若还有可显示标签则继续全屏，最后一个关闭或切换工作区/会话时退出。进入等待期间选中目标失效则立即回退。

宿主文档及已接入面板中继的 iframe 支持 Esc。原生网页的 Esc 经 `BrowserTabService` 的 `before-input-event` 转为 `browser:escape {tabId}`，仅接受当前代、活动、宿主前台且非 Agent 输入中的 guest；右侧再核对当前全屏网页身份后退出，不结束网页或改变页面状态。没有面板中继的内嵌原生查看器仍可使用顶部退出按钮。Windows/macOS/Linux 共用 Chromium API；Linux X11/Wayland 由 Electron 适配，没有平台专属窗口命令。

组件回归见 `test/unit/right-workspace-ui.spec.tsx`，网页输入边界见 `test/browser-tab-lifecycle.mjs`；真实 App、原生 webview 与截图验收入口为 `test/e2e/right-tabs-fullscreen.spec.ts`，使用独立沙箱和本机 HTTP 页面。Windows Electron 已验证深浅主题、整屏几何、顶栏隐藏/唤出、网页与文件切换保持全屏、原 guest/草稿保留、按钮退出和网页内 Esc；截图位于 `.tmp/ui-captures/right-tabs-fullscreen/`。macOS、Linux X11/Wayland 尚未实机验证。

## 固定到右侧（2026-10-28 定稿）

标签栏不提供新建入口（2026-10-28 用户要求删除顶栏 `+` 与标签右键「新建标签页」；同日曾短暂做过「文件 / Git / 终端 / 浏览器」新建菜单与新建文件通道，一并撤除）。新开网页只剩：收藏侧栏主页按钮（无可见主页时才新建，否则切到已有主页）、无网页标签时的空状态「新建标签页」、聊天 / 收藏里的链接打开；右侧没有「再开一个新标签页」的独立入口。

**固定到右侧（统一入口）**：会话（GUI 与 CLI 终端）、普通终端、内置实用功能（定时任务 / 使用统计 / 记忆整理 / 扩展管理）和扩展导航入口都可以「固定到右侧」，入口一致：

- 左栏工作会话 / 终端行右键菜单、实用工具磁贴右键菜单（新增，含「分屏显示」；键盘 Shift+F10 / ContextMenu 键）、常用扩展的 ⋯ 菜单、扩展导航树右键菜单；
- 中栏每格悬停工具栏中央三点把手的菜单（单屏与分屏都有）。

已固定时同一位置显示「移回中栏」。文件夹节点、直接打开的 `ext:` 扩展面板、空选择器与 scheduled 服务页不提供该项。固定的标签是项目级（与扩展标签一样不随中栏会话切换而隐藏），不占用 Pin，资源胶囊不随之切换；固定时自动切到右屏并选中该标签。

**实现**：`src/renderer/src/rightDock.tsx` 是唯一入口。`useRightPin()` 给出 `canPin / isPinned / pin / unpin / moveToCenter / reveal`：扩展导航入口沿用 navigation `placement: 'tab'`（`setExtensionPlacement`，仍要求 `moveBefore` 保活 iframe，不支持时提示不改状态）；会话与内置工具经 `requestRightPin` 通道交给 `SideToolsPanel`，后者以 `{ kind: 'session', sessionId, title, chat }` / `{ kind: 'utility', sel, title }` 内容开关标签，并用 `publishRightPins` 发布当前项目已固定集合供菜单判定。

**同一实例移动**：会话视图（`TerminalView` 按 sessionId 注册截图 / 粘贴并推送 pty 尺寸；GUI `AgentChatView` 持有 composer 草稿）与内置工具面板在中栏只挂一份。中栏用 `DockSurface` 包住每个会话视图与内置工具层内容，右侧固定标签渲染 `RightDockHost` 登记宿主（key 为 `session:<id>` / `utility:<sel>`），同一 DOM 用 `moveBefore`（不支持时 `appendChild`）移入右侧，xterm 缓冲区、滚动、选区与 GUI 草稿不重建；`visible` 改由右侧标签是否当前显示决定。固定的会话强制留在中栏视图 LRU 内，固定的工具层关闭后也保留实例。中栏若此时要显示该内容，对应槽位 / 工具层显示「此内容正在右侧面板中显示」占位，提供「在右侧查看」与「移回中栏」。工具面板自带的关闭在右侧时只取下标签。右侧工具栏提供「移回中栏」（取下并在中栏选中：会话走 `jumpToSession`，工具经 `onCenterUtilityRequest` 交给 App 的 `selectUtilityPanel`）与终端已退出时的「重新启动终端」。关闭标签只是归还视图，不结束进程。

**持久化与清理**：会话 / 工具标签写入标签偏好，重启后恢复（会话进程本身是否恢复取决于会话层）；`validateRightWorkspaceSaved` 只接受合法 `sessionId` 与受支持的内置工具 ID。设置的单一宿主通过 `DockSurface` 在中央和右侧移动；专用桥在后台准备设置，恢复右侧标签时重新准备，未保存草稿或模态设置阻止代理移动或关闭，用户固定的标签受既有保护。通用 utility 入口仍拒绝设置，必须走设置专用桥。会话表初始为空，`sessions` 动作只清理本次运行中见过、后来删除或归档的会话（已归档在表内也清理），连同相关历史操作；未加载到的会话保留标签并显示「会话不存在或尚未加载」。改名同步标题。

**CSS 约束**：`DockSurface` 的两层包装是 `display: contents`，但会改变 DOM 父子关系。凡以 `.center-panel … > 会话视图根` 直接子选择器表达的规则（工具层打开时藏起会话、分屏显隐、层级、查找偏移），都同时写出 `> .right-dock-home > .right-dock-surface >` 包装路径；`test/right-dock-css.mjs` 静态守卫（2026-10-27 初版只包 Shell 时漏了工具层遮挡规则，单屏打开工具时终端字会透出）。

## 打开、保活与保存

- 扩展从底栏“右侧标签页”进入统一标签栏；工作区内跨会话可见，位置以扩展导航为唯一保存源。`extensions` reducer 动作同步新增/改名/召回，扩展被删除时清理该扩展的历史。关闭扩展标签即召回，撤销关闭会重新停靠；它的主页面通过 `ExtensionSurface` 原位保活并移至右侧容器，不创建第二份实例。右侧隐藏页保持 inert，扩展不额外显示文件工具条；资源面板保留原选择。当前扩展在右屏露条态通过宿主透明手势层触发点击/悬停切屏，激活后恢复 iframe 交互；隐藏标签及关闭的右屏不启用手势层。详见[扩展工作台](extensions.md)。
- 页面宿主只有在保活移动实际成功后才隐藏其原位置；缺少 `moveBefore` 或调用失败时显示错误并保留原 DOM，不退回可能重载 iframe 的普通移动。向右移动失败时请求恢复中栏，并忽略被后续召回取代的旧位置请求；召回中栏会取消待处理的右屏切换。通过位置更新入口离开右侧时，先把仍连接的 iframe 迁回中栏，再保存位置；迁移失败保留右侧标签。保存回执失败或不匹配时读取同一工作区和来源的导航状态：确认已更新则接受，确认未更新才移回原标签，无法确认或回滚失败则明确报告。Windows Electron 故障注入验证过两方向错误可见及草稿保留；外部导航推送变更同一项目与来源的多个扩展位置时，也会先迁移全部活动页面；失败时回滚本次已迁移的页面、保留旧视图并提示错误。已保存的后端导航与前端可暂时不同步，需重试更新；扩展删除或来源更换不在该保护范围，其他平台尚未实机验证。

- 文件树、文件 / 内容搜索结果单击复用工作区范围的临时预览；双击、搜索结果 Enter 或编辑将其保留。打开不同文件时的双击带 `replacePreview`，避免在异步读取未完成时留下旧预览。聊天结果默认打开来源会话的普通标签，不占用审核中的文件或 Diff；同一作用域内相同源根与相对路径的内容去重，工作区与会话范围可以各有一份。
- 文件入口经 `fs.resolveRef` / `fs.statRef`，保存经 Ref 写通道与基线 mtime 冲突保护。外部文件只读，失效根身份会报错。异步打开携带来源会话和工作区。切到其他会话后迟到的会话链接仍归原会话，当前标签保持选中。文件预览中的文件和部件链接沿用该文件标签的归属。
- 每个打开文件独立保留 CM 实例、编辑草稿、查找、滚动和 undo；其他会话 / 工作区的文件实例隐藏保留。只有当前文件注册批注来源，并核对选区属于本实例。临时预览替换或关闭前必须 flush；失败时保留原标签与草稿并提示。
- 源仓从右侧仓库树打开，检出从 Git 详情工具栏分支旁的 [Worktree](git-repo-tree.md#从-git-工具栏切换-worktree) 入口打开。同一项目的仓库标签按检出路径复用，各自保留所选 Diff 和提交草稿。切项目或源根版本时 Git 请求与组件重新绑定；Git 提交草稿在本次运行期间可恢复。仓库详情内「在新标签中打开 Diff」创建独立文件差异视图。
- Git 工具条「审阅」眼睛图标或聊天文件卡打开 `review` 标签；按 owner kind/id 复用标签，切换轮次和文件进入撤销历史。标签偏好只保存会话/消息/路径身份，正文经 `turnChanges` IPC 按需读取；失效消息显式提示，不自动显示别的轮次。窄容器中文件列表移到 Diff 上方。完整交互与文件回退边界见 [turn-checkpoint.md](turn-checkpoint.md)。
- 工具面迁移中的内部审阅桥接可后台打开或更新 AI 自建且未显示的会话审阅标签，不改当前选择。后台请求不得改变当前显示的审阅内容，工作区共享、固定或用户持有的已有标签受到替换保护。主进程核对 owner 工作区、目标轮次与所选文件的调用者读取范围，并在派发后重验。快照对越界文件或其他工作区的审阅身份做脱敏。该桥由公开 `host.panel.open` 使用。
- 内部面板打开桥的设置、文件及图片支持中央与右侧；其他内容种类和位置仍在实现，显式请求尚未实现的位置会报错，不静默改放其他位置。完整位置支持完成前不得公开注册候选工具。
- 程序化聚焦左右页面前取消已有悬停切页计时，并沿用程序化切页的短暂悬停抑制；尚未提交的页面选择也参与判断。聚焦后仍等待实际可见和动画结束，期间真实页面或目标发生变化时返回结果不确定。
- BrowserPage 与 webview DOM owner 跨项目 / 会话保持稳定，后台仅改变停放样式和命中能力，不移动或重建 guest。原生壳新增、关闭、URL 更新和激活同步到统一标签。偏好水合时，每个恢复的原生壳只绑定一个右侧标签。撤销关闭网页时，主进程只创建一个后台壳并恢复原生导航栈。右侧按请求回执将它绑定原逻辑标签，未提交的网页壳只用于加载。显式带会话身份的后台网页即使所属项目尚未水合也纳入生命周期管理。恢复壳不抢占文件审核。后台 Worker 创建网页时用绑定会话 owner；弹窗、主页链接和交互部件的开页动作继承父页面当时的范围和 owner。
- 会话归档时，逐标签先 flush 文件草稿，再卸载归属该会话的文件、Diff、审阅等内容并关闭网页原生壳与 guest。工作区共享资源继续可用。归档只保存可恢复的标签描述，网页进程、页面内存、滚动和未提交表单随 guest 销毁。恢复会话后自动恢复入口，网页在需要显示或被后台工具请求时重新加载。关闭或保存失败会提示，归档与快速恢复交错时等待关闭结束后再恢复。
- 人工新建浏览器标签时显示由宿主绘制的新标签页；新标签页和侧栏使用同一项目的收藏树。侧栏可创建、重命名、删除文件夹，并将收藏或文件夹移动到其他文件夹；新标签页提供搜索、多选和整理。收藏树尚未水合前禁止修改，写回失败有提示。

## 状态与 IPC

`useWorkspaceFile.patch({ rightWorkspace })` 经工作区配置 IPC 写回标签偏好。`rightWorkspace.version=1` 分别保存标签的 `scope` 和 `pinned`，并保存每会话选择、资源类型和收起状态。旧记录缺少 `scope` 时，根据原有共享行为推导归属，并保留原来的固定状态。普通临时预览、历史及文件正文不进入快照，归档中的临时预览例外。归档关联标签另以 `muster.right-workspace.archived-tabs.v1` 存入本机 localStorage，使尚未水合的其他工作区也能在重启后恢复入口。网页记录不携带旧 browserId。归档记录在标签恢复后保留至用户关闭，读取或写入失败会提示。恢复先校验来源身份并重新分配标签 ID，迟到的水合保留刚打开的内容和选择，并按内容身份及归属去重。工作区偏好实际写入失败时，右侧工作面显示可关闭提示。

项目收藏保存在控制根下的 `.muster/bookmarks.json`。侧栏、工具栏和新标签页共用 `workspaceBookmarks:read` 取得的快照。编辑通过 `workspaceBookmarks:change` 提交单项操作，主进程绑定工作区控制根，按项目顺序在磁盘最新树上执行，再原子写入并返回快照。渲染层在收到保存回执后更新，窗口 tip 提示读写错误。节点保留 ID、名称、网址或子节点、添加时间、描述和本地 PNG 图标。每层最多 200 项，嵌套深度最多 8。文件夹移动校验目标祖先，旧节点无时间时显示未知。

首次加载时，宿主从 `workspace.json` 的 `rightWorkspace.bookmarks` 和 `bookmarkDefaultsVersion` 迁移。新文件原子写入并回读校验成功后，宿主重读最新的工作区配置，再清理与迁移摘要一致的旧字段。迁移中断时可用已校验的新文件重试清理。期间的标签保存保留旧字段和最新标签状态。独立文件损坏会报告读取失败，保留现有文件和迁移来源。

桌面应用的收藏侧栏顶部按钮打开或复用当前工作区共享的主页。远程网页的 HTTP(S) 收藏在访问设备的新标签页打开，主页按钮和宿主文件等收藏会提示使用桌面应用。侧栏的文件夹新建与重命名通过右键菜单进入新标签页共用的收藏弹窗。

新标签页壁纸、材质透明度与模糊是本机全局外观偏好，不属于项目收藏；壁纸图片保存于渲染层 IndexedDB，选择及调节值保存在 localStorage，详见[内置浏览器](builtin-browser.md#保留能力与交互)。

工作区首次加载默认收藏时，按文件夹名称复用已有目录，按规范化网址跳过已有网站，并保留原有节点与顺序。`bookmarkDefaultsVersion` 与收藏树一起保存在独立文件，空树也保留初始化版本。若合并超过收藏树限制，保留原树并提示，腾出空间后下次加载可重试。

浏览器经 `browser:*` IPC 与全局 BrowserTabService 交互。`browser:tabs` 中的可选 `workspaceId/sessionId/scope/openerId` 描述展示归属。浏览器壳绑定标签时通过内部 `browser:setOwner` 校准归属，使子页面继承工作区或会话范围。Pin 状态保存在右侧工作区偏好中。全局 `browser.tabs` 配置按 URL 同序保存 owner，登录态走 `persist:browser`。工具 `browser.open` 的来源 owner 是展示元数据，不赋予新权限。

`host.panel.run` 显式打开自己的后台 HTTP(S) 浏览器标签并要求聚焦时，可以展示隐藏扩展会话的既有页面。主进程绑定调用者 session，Renderer 在完整标签模型中核对 owner 和 URL，`presentWeb` 将唯一匹配项提升为 workspace scope 并选择；保留标签 ID、来源 session、Pin 与同一 guest，不复制或导航页面。后台查询及其他会话的隐藏页不走该路径，活动编辑器有未保存修改时仍拒绝切换。展示后页面在本工作区各会话间共享，由原有 owner 同步与持久化处理。

每个工作区和会话最多保留 60 个操作。打开标签、关闭标签、同一标签换内容以及 Chromium 网页导航使用同一对「撤销」「重做」。批量关闭记一步并保留标签顺序与选择。点选已有标签、单纯刷新、偏好水合与后台 AI 动作不增加步数。常规文件预览在原标签回放，后来已保留或编辑的文件保持原编辑器，旧内容通过临时预览查看。网页的前后位置保留 Chromium 的索引，关闭后从检查点恢复原逻辑标签。详见[面板与内容历史](panel-history.md)。

## 设计初衷（2026-10-26 与用户定稿）

> 依据 campaign-intent-drafts/D08-D00.md 草案定稿（用户 2026-10-26「不抽查直接定稿」）；歧义点处置：22 项卡片决策＋长尾按草案推荐，明细见专项账本「意图定稿决策」节。

- 为谁/什么场景：用户在右侧标签栏并行查阅文件、图片、网页、Git 仓库、独立 Diff、轮次审阅和扩展，手动打开的资源可供当前工作区各会话查阅，会话打开的资源随原会话显示。
- 为什么这样设计：标签归属决定在哪些会话可见，Pin 让用户标记并保护重要标签。单击复用临时预览，双击、编辑或 Enter 保留。异步打开和关闭完成后复核工作区、会话和根版本。标签隐藏时保留编辑器实例、草稿、撤销栈和滚动位置，webview 跨项目保留 guest。右页最多保留 60 个撤销操作，左栏历史只记录右页节点。外壳用 `overflow:clip` 约束窄屏内的网页位置。
- 明确不做：临时预览/历史/文件正文不进标签快照；Git 提交草稿不跨应用重启持久化；后台 Worker 语义操作不要求用户显式打开所属工作面，也不能借此把窗口切到前台；编辑保存走既有 autosave/Ref 通道，不在标签偏好里复制一套保存逻辑。
- 歧义点：Git 提交草稿重启即丢（代码证实为 useRef 内存态），而聊天输入草稿已持久化（`muster.composer.drafts.v1` 按工作区，见 ui-state-persistence §表）——两类「用户敲的草稿」下场不一致。A=接受（提交草稿生命周期=「即将提交」的短促文本，重启丢可重打；review 不把丢草稿当数据丢失缺陷）／B=补持久化（按仓路径落 localStorage，与 composer 草稿同族）。推荐 A——composer 草稿是跨回合高频长文，commit 草稿是提交前一次性内容，成本收益不对等；若用户实际被打断过提交则升 B。
