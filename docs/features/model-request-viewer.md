# 模型请求录制

在普通 Core 会话、扩展的 AI 侧栏或调度 Agent 输入框执行 `/record-requests`，开始录制并打开「模型请求」面板。录制中，输入框右上角常驻「录制中」，点击即可重新打开面板。面板的「记录本会话请求」开关可以停止或恢复采集。`/record-requests view` 直接查看已有记录并保留当前录制状态。命令由工作台输入框本地执行，录制默认关闭。关闭面板、切换会话或重启会保留各会话的录制状态。清空对话会清除对应记录并停止录制。

左侧选择一次发送，右侧「内容」按协议字段呈现系统提示、顺序消息、工具调用、工具结果及参数。工具定义可展开。宽窗口并排显示调用列表与阅读页，窄窗口通过顶部横向列表切换调用。每页 50 条，刷新重新获取当前页。「原始请求体」默认将合法 JSON 以两空格缩进、行号和语法着色展示，保留键顺序、重复键、数字字面量与字符串转义。关闭「格式化 JSON」可逐字核对收到的 UTF-8 原文，非 JSON 或未发完且无法解析的正文也显示原文。开发服务器启动时预构建 JSON 编辑器依赖，避免流式输出时首次打开编辑器触发 Vite 整页重载。

入口由 `ChatSurfaceView` 接入统一 Composer 和面板。`ModelRequestRecording.tsx` 维护该会话的当前开关，接收主进程 `modelRequests:recordingChanged` 推送，同步应用主窗、扩展独立窗及已连接网页。调度单窗和并排对话都绑定各自工作区。普通 Core 和扩展 AI 侧栏使用 GUI 会话 ID，调度使用 `scheduler:<workspaceId>` 存储键。请求 IPC 校验可采集的 GUI 会话或已打开的调度工作区后，读取或更新对应记录。

## 导出实际调用

调用列表上方的「导出当前调用」只导出选中记录；「导出全部调用」导出本会话当前仍保留的所有记录，包含其他分页，按调用 ID 从早到晚排列。导出不改变记录开关，不发起模型调用。按钮在没有记录或保存进行中禁用，取消保存不报错；保存失败显示原因。会话仍在输出时也可以导出已经采集完成的 HTTP 发送。

桌面客户端通过 Electron 原生保存对话框选择 ZIP 文件位置。解压后包含：

- `requests/<调用ID>.json`：该次发送的原始字节，不经过 JSON 解析或格式化，保留重复键、数字字面量、空白、字符串转义及未完整发送的正文。扩展名不保证内容是合法 JSON；发送中断时也可能以不完整的 UTF-8 字符结尾。
- `manifest.json`：`format: "muster-model-requests"`、`version: 1`、导出时间、会话 ID 和 `requests` 清单。每项保存调用 ID、时间戳、模型、协议、原始字节数、`complete`、`omitted`、`bodyFile`、正文 `sha256` 及 `compression` 公开关联信息。超限未保存的正文没有对应文件，`bodyFile` / `sha256` 为 `null`，界面报告缺失数量。清单不导出 Pi 原生会话文件定位信息；压缩前来源正文仍在窗口内按需对照。

入口为 `ModelRequestsDialog.tsx` → preload `agentSession.exportModelRequests(sessionId, call?)` → `agentSession:exportModelRequests` IPC → `modelRequestExport.ts`。主进程校验会话与调用 ID，只允许有本地窗口的桌面请求打开保存对话框；网页客户端调用会收到明确说明。`modelRequestStore.visitModelRequests` 使用同一 SQLite 读快照逐条核验长度和 SHA-256，避免滚动淘汰造成清单/正文不一致。ZIP 逐正文写入目标目录下的临时文件，全部成功后再替换用户选择的文件；读取损坏、记录已淘汰或写入失败不会覆盖原文件，临时文件会清理。导出过程同步读取/压缩，极大正文或大量重复调用可能延长保存等待；没有额外截断导出内容。

保存对话框及文件写入共用 Electron/Node 跨平台接口，没有平台专属 Shell 或外部压缩依赖。导出包含实际提示中的代码、附件和用户提供的敏感内容；不包含采集器从未保存的鉴权请求头、响应正文或服务商内部改写。

## 采集与归属

Core 列表标出每次实际发送中识别到的压缩项数。选中调用后的「压缩」页按项显示工具结果摘录、模型撰写的工具结果摘要、阶段检查点、检查点展开或 Pi 会话摘要。每项列出 HTTP 正文的字段位置及其实际文本。展开来源可分页对照压缩前的公开原文，每页 6,000 个 UTF-16 码元；阶段检查点另列上代摘要及本代来源。字符数取自文本，不代表模型 token 或计费节省。旧记录、发送中断或来源文件缺失时显示可核对范围。调度录制提供实际请求正文。

左侧「压缩当前会话」复用聊天输入框的手动压缩操作，作用于当前会话，选择历史请求仅改变阅读位置。进行中的模型回合由原有宿主忙态守卫保护。压缩成功后，下一次实际发送可以看到生效的会话摘要。操作本身不启用请求记录。

`workerEngine.ts` 和调度的 `piProvider.ts` 为各自 `ModelRuntime.stream/streamSimple` 安装异步调用作用域。`modelRequestCapture.ts` 在每个进程用一组 Node/Undici 传输诊断订阅，在模型作用域内的 HTTP POST 上按发送顺序收集正文块，在发送完成时提交。连接关闭时解除该运行时的采集，最后一个运行时关闭时退订传输事件。重试的 HTTP 请求各有记录，发送中断时保留已观测的部分并显示「发送未完成」。模型调用作用域以外的工具网络流量与鉴权请求头均不入库。完整发送表达宿主端的发送边界；中间网关以后的处理由服务商管理。

`src/main/agentSession/modelRequestStore.ts` 在应用的 `agent-inputs/model-requests.sqlite` 中保存记录。所有会话共用 50 MB（50,000,000 字节）持久库上限，包含索引、调用清单和压缩块。提交时从最早调用开始淘汰，SQLite 写事务的临时回滚日志可短时额外占用磁盘。单次请求独自超限时保留调用信息，界面标记正文超限。升级时迁移旧版会话请求库，记录开关默认关闭。

每条调用保存完整的有序分块清单和正文 SHA-256。相同内容块按 SHA-256 共享一份 gzip 数据。删除旧调用、清空或删除会话时，在同一个 SQLite 事务中删除清单，最后一个引用消失才回收内容块。读取在同一个快照里重组并核验长度及哈希。停止后重新开始会产生新的记录标识，中途跨过停止点的发送不能写入。主进程通过 `agentSession:modelRequests` 返回元数据页，`agentSession:modelRequestBody` 只读取选中记录。界面位于 `src/renderer/src/agentChat/ModelRequestsDialog.tsx`。原始正文可含提示中的代码、附件和用户提供的敏感内容。

## 验证与边界

开启记录后，捕获器把发起调用时的 Pi 分支叶子随传输作用域带到每次 HTTP 发送。仅匹配该分支有效投影和对应协议正文中逐字吻合的工具结果或检查点。工具参数、用户粘贴的摘录和被后续投影取代的旧结果均不作为新压缩事件。每次重发独立记录当次携带的项目。同一摘要可连续出现在多次调用中。记录库只追加关联元数据，随调用在同一事务内滚动回收；来源正文按调用及来源 ID 从 Pi 原生会话按需读取，界面不能指定文件路径。

- `node test/model-request-storage.mjs` 使用临时库验证真实 50 MB 滚动淘汰、共享块的最后引用、重复记录、超限单条和旧库迁移。
- `node test/model-request-export.mjs` 使用临时库验证跨 50 条分页的全部导出、单条/会话隔离、原始字节（含不完整 UTF-8）、清单、超限缺失项、损坏检查及保存失败不覆盖已有文件。组件测试覆盖选中/全部参数、保存中禁用、取消、失败和缺失正文反馈；Electron 用例覆盖真实 UI → preload → IPC → ZIP，与本地 HTTP 接收正文逐条比对，仅模拟系统文件选择对话框。

- `node test/model-request-capture.mjs` 通过 Pi SDK 分别发出 OpenAI Chat Completions、Responses、Anthropic Messages、Azure Responses、Google Generative AI 和 Mistral 的请求，将记录与本地 HTTP 接收端逐条比对。覆盖服务端错误响应、并发录制隔离和其中一个运行时释放后的持续采集。
- `test/e2e/model-requests.spec.ts` 从三处真实 Electron 会话的输入框启动录制，经快捷入口打开面板并逐字核对本地 HTTP 接收正文。也覆盖 Core 的压缩来源、忙态保护和 ZIP 导出。`test/unit/model-requests.spec.tsx` 验证本地命令、历史浏览、快捷入口显隐与焦点恢复、录制事件同步和过期读取。`test/core-context.mjs` 检查三级检查点的上代与来源清单及单条语义摘要。
- 采集范围为内置 Core GUI（包括扩展 AI 侧栏）与交互调度会话的上述 HTTP 模型请求正文。外部 Harness 自管连接、扩展 SDK 的独立模型网关调用、无头定时任务和服务商内部改写超出此范围。
