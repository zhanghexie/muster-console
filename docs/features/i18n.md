# i18n 多语言（中文 / 英文）

## 功能职责

应用界面支持中文（zh-CN，源语言）与英文（en）两种语言，默认跟随系统语言，可在设置「外观」页手动切换，即时生效、无需重启、重启后保持。终端与 Agent 输出（CLI/LLM 生成文本）和第三方扩展的自有内容不由工作台翻译；内置日报面板自行提供中英文文案。

## 关键文件与入口

| 文件 | 职责 |
| --- | --- |
| `src/shared/i18n/index.ts` | i18next 实例 + 语言解析/切换/订阅。无 React 依赖，主进程/渲染层/共享层三方共用。模块加载即同步初始化（默认中文）；给 zh-CN 注册**身份资源**（key→key，由 en 词条表 keys 推导）——i18next 对 missing-key 回退的 key 不做插值（含 `{{x}}` 的 key 会原样露出，如看板「归档 · {{count}}」），身份资源让中文走正常翻译命中从而插值生效 |

## 数据流

```
设置切语言（渲染层）                     主进程侧改 locale（Agent 工具等）
changeLocale()                                  │
  ├ applyLocaleSetting() → i18next.changeLanguage → languageChanged 事件
  │    └ react-i18next 的 useTranslation 订阅 → 全部组件重渲染
  │    └ 非 React 的 t() 下次取值即新语言
  ├ localStorage 缓存（muster.locale.cache.v1，防启动闪错语言）
  └ window.api.config.update({ locale }) → ConfigManager 落盘 config.json
       └ 主进程 applyLocaleSetting(app.getLocale()) + 广播 locale:changed
```

启动：`localStorage` 缓存先刷（缺缓存 = 中文）→ React 挂载前 `initLocale()` 用 `config.get()` 校正 → 之后以 `locale:changed` 保持同步。`document.documentElement.lang` 随生效语言更新。

## 使用规约（写代码必读）

1. **key = 中文原文**。组件里 `const { t } = useTranslation()`（react-i18next，语言切换自动重渲染）；非 React 代码（shared 纯函数/主进程/模块顶层）直接 `import { t } from '<path>/shared/i18n'`。key 必须是字面量，禁止 `t(变量)` 传非数据标签。
2. **缺词条安全**：en 没有对应词条时界面回退显示中文原文，绝不露裸 key。因此迁移可以增量进行；但每批迁移必须把词条补齐（覆盖率脚本会拦）。
3. **插值**：模板串 `${x}` 改成 `{{x}}` 占位、调用传 `{ x }`。**禁止传 `count` 选项**（触发 i18next 复数后缀机制，会去查 `key_other` 变体导致双语言都查不到）；占位符用 `{{n}}`、`{{name}}` 等任意非 count 名。英文复数敏感的串交给 Intl（见 `shared/relativeTime.ts`）或按单复数分 key。行为由 `test/i18n-core.mjs` 锁定。
4. **数据驱动标签**：`SETTINGS_TABS`/`SETTINGS_FIELDS`/`THEME_UI_GROUPS` 等数据里的标签保持中文原文，在**渲染/组装点**调翻译（如 `collectSettingsHits` 内 `t(item.title)`）。数据文件禁止在模块层调翻译（语言切换后不会更新）。这类 key 在覆盖率脚本里表现为「未引用」提示，属正常。
5. **不翻**：console 日志、注释、className/id 等代码值、逻辑值（'dark'/'running'…）、用户数据（会话名/路径/主题名）、发给 LLM 的提示词正文、终端与 Agent 输出及第三方扩展的自有内容；内置日报面板自行提供中英文文案。**用户可见的 error.message 算界面文案**：throw 后经 IPC 直达界面展示、或作为 `{ok:false,error}` / `warning` 回传渲染层展示的报错，其前缀/归类语走 `t()`；内嵌的上游原始报错、错误码、网关返回体等诊断细节可保留原文。console 日志不翻。
6. **比较/对象键的字符串绝不包翻译**——只包显示用途。
7. 时间格式化不要手写语言文案：用 `shared/chatTime.ts` / `shared/relativeTime.ts`（内部 Intl + 词条），或自己 `Intl.DateTimeFormat(locale)`（locale 取 `getResolvedLocale()`）。中文的「M月D日」类格式保留手写分支（Intl 的 zh 输出是 `8/29`，与既有习惯不符）。
8. 排序 locale 用 `getResolvedLocale()`，不要再硬编码 `'zh'`。

## 已知边界与注意

- 「跟随系统」解析：`zh* → zh-CN`，其余 → `en`；`supportedLngs` 只有这两种。新增语言 = 新增 `locales/<lang>.ts` + index.ts 注册 + resolve 分支 + 设置下拉加项。
- CDP 测试脚本若断言了中文 UI 文案，切英文会失败；迁移新区域时同步更新相关断言（或让测试先切回 zh-CN）。
- 英文字体（Geist/Inter）比中文窄，迁移区域首次切英文时复查截断/列宽布局。
- 词条抽取支持一行多个键，跳过注释及字符串值中的伪键；同一行被删除但仍引用的词条也参与维度门检查。指定的静态 CSS 模板只遮盖真实 CSS 注释，CSS 引号中的文字与同一行的其他文案仍参与扫描。
- GUI 权限选项以实际返回的标签和说明枚举词条后，才逐字面量遮盖其数据定义；邮箱读取、唤醒投递的已核对函数属于代理工具协议，保留原文；交互部件的协议回执也保留原文，而工作台自身的已知错误在展示边界翻译。以上处理不改变已存数据或第三方诊断。
- 会话分叉、投递、清理及安全审批错误只翻译已识别的宿主说明；外部错误及已保存的审核记录保持原样。使用统计中仅翻译已知的宿主默认失败说明，历史 Cursor 的回落名称仅在用户没有注册同名运行时的情况下翻译。
- 新导入手机应用记录及自动生成的飞书连接名，仅在来源标记、字段和原文一致时翻译；未标记的历史记录及外部真实内容保持原文。记录或连接名经显式编辑后清除相应标记；占位来源表的每个键由覆盖检查验证英文词条。
- 会话内交互部件与网页区 guest 通过兼容旧版本的可选语言字段切换新运行时的宿主默认文案；作者内容、外部错误、面向模型的原始诊断和已保存的旧 HTML 均不改写。运行时 JavaScript 另有专门的来源与词条覆盖检查，并由总覆盖检查调用。
- 附件文档转换仅供模型工具与附件上下文使用，其内部诊断保留原文；网页凭证损坏的细节仅写诊断日志，用户可见的网页访问错误另行翻译。覆盖检查只在已核实的函数或字面量范围内排除这些内容。
- 旧记忆抽取管线及其归纳、审查、状态和重试助手目前没有生产调用方；显式全仓审计仅排除已核实的旧管线文案，并守卫生产代码新增引用时必须重新判断这些提示的展示路径。
- 扩展清单校验和卸载提示在扩展中心展示时翻译，保留可供发布与诊断使用的原始原因。反馈错误经 IPC 或历史记录渲染翻译。进程监控在生成快照时翻译宿主标签，消息渠道和存储维护名称在设置页渲染时翻译。
- 迁移范围：设置弹窗、命令面板、左栏、看板、时间文案及扩展域已有翻译；手机主页、导航、连接设置、飞书接入以及未改动的内置应用字段和操作已接入切换。日常门禁检查全仓静态翻译键、渲染层裸中文和已登记的动态文案；它不证明主进程所有错误都已翻译。显式 `--audit` 也扫描主进程与共享层，其中的中文可能是界面提示、协议或用户数据，需按实际调用方判断，不能把命中数量当作未翻译界面数量。字符串扫描按原始语法位置检查，JSX 检查直接文本、人可见属性及简单条件分支，但不覆盖任意动态表达式；新增界面一律直接走 t()。
