# 桌面控制基础设施（开发中）

`host.desktop.list` 提供只读元数据。Windows、macOS、Linux X11 和满足合成器依赖的原生 Wayland 在主入口装配可见桌面运行时，共用 Cua 窗口选择、截图、语义读取和点击。Windows 和 macOS 还支持聚焦、启动与显示器坐标下的拖拽、滚动和键盘输入。显示器截图由 Electron 提供，Linux 需要能唯一匹配显示器的截图源。窗口观察 ID 仅供观察。实施计划

## 窗口截图与点击

`list(view: "windows")` 从 Cua 的可见窗口签发有界、同回合的选择引用，支持 `windowOffset` 与 `limit`。`look(mode: "both", windowId)` 在私有 Cua 会话里一次读取 PNG 和语义树，返回 `window-pixel-v1` 坐标与 Muster 签发的 `captureId`。`act` 用 `target: { windowId, captureId, x, y }` 点击或双击，底层把该图像对应的私有 Cua 引用交回同一驱动会话。整屏 `look(surfaceId)` 用于观察显示器、选窗以及 Windows 和 macOS 的其他显示器坐标动作。整屏坐标点击返回 `window_capture_required`。

`cuaDesktopBackend.ts` 统一 Cua 会话、发现、停止和释放。`cuaWindowList.ts` 保留同回合的可见窗口身份及几何，读取前后和派发前在驱动上核对。`cuaSemanticRuntime.ts` 绑定可信任务、目标、快照、动作去重和会话生命周期。点击前验证像素边界，派发后消耗观测。同一可验证请求的重试返回回执。窗口移动、停止、过期或重新观察使旧图失效。`screenRuntime.ts` 校验实际 PNG 并写入任务所属的产物存储和截图审计。可点击的截图要求驱动提供明确的窗口绑定，未绑定时返回 `window_capture_unavailable`，语义树可另行查询。驱动只返回有效 PNG 时，`semanticStatus` 为 `unsupported`，窗口坐标仍可用。X11 的被动 Esc 与原生 Wayland 的 Stop helper 分开配置。Windows、macOS、X11、Wayland 的合同模拟测试共用 `test/desktop-cua-window-control.mjs`。

`host.desktop.list` 的 `view: applications` 是可选 Cua 应用发现路径：只有宿主显式配置 `desktopAppDiscovery` 与桌面运行、且调用拥有当前活动租约时才执行；默认显示器和窗口元数据路径保持原样，三个平台的可见桌面宿主均已装配应用发现。首次请求支持有界名称搜索、运行状态过滤和每页 1–10 条；后续通过快照 ID 与偏移分页，快照绑定可信会话、任务和回合，停止、身份变化、重新查询或 30 秒过期后失效。调度器没有现有桌面任务时使用回合内临时元数据身份，任务绑定变化使快照失效，不会因此申请截图授权。缺后端返回 `capability_unsupported`，驱动、依赖、清理和过期错误分别报告；该路径不截屏、聚焦或启动应用，结果中不暴露 PID、路径或可操作窗口身份。macOS 应用行可提供 bundle identifier 作为 `launch.appId`。驱动无服务端分页，仅处理前 5000 行、保留至多 2000 条匹配结果，`total` 只是有界快照数量，覆盖始终标为未验证。Windows 的来源是可见/前台窗口、开始菜单快捷方式及 UWP；macOS 来源是面向用户的运行应用和选定应用目录；Linux 来源是 `/proc` 与 XDG 桌面项，可能包含非应用进程，宿主会向驱动转发 `XDG_DATA_HOME`、`XDG_DATA_DIRS` 和区域设置。Linux 的 active 为未知，运行行是否安装也未知；Wayland 窗口覆盖依赖合成器。各平台都可能静默遗漏项目。Windows 隔离 Electron 夹具在真实提示窗和固定 Cua 驱动下验证了适配器及第二页，仅输出汇总；调用者和任务身份由夹具模拟。macOS 隔离 Electron 夹具已在真实驱动下验证应用发现。Linux 尚未真机验证。此只读应用路径不经过普通元数据列表的持久审计；按当前产品裁决不为它新增强制审计链，保留必要故障诊断。

应用发现以统一的桌面会话判定识别 X11 和原生 Wayland。`XDG_SESSION_TYPE=x11` 与非空 `WAYLAND_DISPLAY` 冲突，或 X11 缺少 `DISPLAY` 时，发现覆盖记录为未知。驱动只在同一判定为 Wayland 时启用其 Wayland 模式。固定 Cua Driver 0.59.4 的 Linux `launch_app` 按空白拆分命令并直接创建进程，无法可靠解释含空格或引号的 XDG `Exec`。Linux 启动仍需按桌面项规范适配并真机验证。[上游 Linux 启动实现](https://github.com/trycua/cua/blob/01207bbf0ddcc0f2bb9642322c4e8b4b02319d1b/libs/cua-driver/rust/crates/platform-linux/src/tools/launch_app.rs#L19-L48)

Windows 的 `look` 在截图后返回有界窗口选择；`windowsComplete=false` 表示有遗漏，窗口枚举失败时 `windowsError` 给出原因，`windowsUnavailable` 统计本页无法设置身份标记的窗口。动作引用绑定会话、截图、显示器、窗口进程和窗口属性代次，调用前重新核对；[SetPropW 受 Windows 完整性级别限制](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setpropw)，系统拒绝设置属性时不签发该窗口引用。正常退出或后续调用触发过期清理时尽力移除属性，异常退出时外部窗口可能暂留标记。坐标是返回图像的像素，裁剪偏移换算后再转换为系统坐标。`act` 经截图证据及 `DesktopActionGate` 派发，`focus` 使用同一窗口引用，`launch` 仅接受存在的绝对 `.exe` 路径。会话中首次桌面写操作要求用户确认；允许后同一用户回合的桌面操作跨应用复用内存授权，最长 30 分钟。下一条用户消息使授权失效；用户插话投递期间暂停发放授权，Pi 消费排队消息时再次撤销；在途确认或操作也必须重新检查回合与有效期。窗口不可用、确认中断或用户拒绝的回合确认在审计中记录有界原因；中断不区分超时和窗口生命周期变化，旧记录不能补全原因。非用户拒绝的确认失败返回明确错误。既有拒绝记录仅在有效回合授权期间被跳过，授权失效后继续生效；截图读取仍遵循原有授权。CLI 原生终端的回车无法总是区分消息提交和交互确认，可能提前撤销授权。各动作需传入稳定 `requestId`；同会话同任务内以相同参数重试返回持久回执，参数不同则拒绝，派发前的校验或确认失败不写入 pending，同 ID 可重试；进入派发后的未完成记录返回未知且不重新派发；如无法确认任务日志已清理，也按未知处理；换新 ID 不具备去重保证。Windows 隔离 Electron 和 PTY Worker 测试覆盖真实截图、焦点、点击、Unicode 输入和进程启动。混合 DPI、多显示器坐标与提权应用尚未验收。按本任务裁决未接入物理接管检测或看门狗，动作期间用户物理输入可能穿插；窗口属性可能被目标进程移除或干扰，前台遮挡仍有残余风险，派发成功不代表目标业务操作成功。浏览器、扩展和 CDP 尚未接入统一权限门。

在 macOS 上，`macDesktopHost.ts` 复用 `DesktopActivityRuntime`、停止状态账本、共享输入座位和持久 `requestId` 回执。显示器截图沿用 Electron 和截图产物链。`macTargetRegistry.ts` 在截图前保留 `NSRunningApplication` 和精确映射到 `CGWindowID` 的 AX 窗口，截图后复核存活及位置并签发随机窗口 ID。授权、屏幕锁定、窗口身份或几何变化会使派发前校验失败。显示器坐标的拖拽和滚动先换算为系统点位，通过 AX 命中测试或窗口层级确认目标，再按 Cua 窗口比例换算。点击和双击使用同一份 Cua 窗口观测。聚焦可能改变窗口位置，后续坐标操作使用新截图。`macVisibleControl.ts` 通过受监管的 `cua-driver mcp --direct` 发送白名单调用，使用嵌入模式把 macOS 权限归属留在宿主进程链。macOS/Linux 上原生进程组信号派发失败时，关闭返回未确认回收，并保留系统错误原因。聚焦需要 Cua 确认精确窗口，应用启动只接收 bundle identifier。语义操作复用 Cua 的有界树与引用机制。窗口身份校验和系统派发存在时间间隔，未知回执不会自动重放。

工具失败通过执行器把 `ok: false` 和 `code` 提到外层，`result` 仍包含结构化详情。`capability_unsupported` 指构建或动作缺少实现，`dependency_missing` 指固定驱动不可用，`permission_required` 指系统授权缺失，`screen_locked` 指 macOS 会话仍锁定。macOS 截图有权限时可以返回 PNG。窗口选择不可用时通过 `windowsCode` 和 `windowsError` 说明原因。隔离 Electron 夹具在 macOS 27.2.1（26B131）验证了锁屏时保留截图和拒绝窗口操作。升级至 Cua Driver 0.59.4 后，同一夹具在解锁会话中通过了截图、窗口选择、精确聚焦、点击去重、中文输入、Command+A、语义树、应用发现和停止按钮，并核对不存在的 bundle identifier 返回失败。窗口流程已在同一真机验证 Cua 窗口截图、坐标点击、回执重放及窗口移动后的旧图拒绝。Windows、X11 和原生 Wayland 的窗口流程仍待真机验证。实际启动已安装应用、签名安装版、权限撤销、物理 Esc 和多屏仍待验收。

Windows 输入经 `TrackedWin32Input` 跟踪本适配器尝试按下的键和鼠标按钮；发生部分派发或释放失败时保留待释放状态，后续清理失败会报告错误。`act` 的 `target.keys` 在现有 Windows 数字虚拟键之外也接受 `Control`、`KeyA`、`ArrowLeft` 等命名按键，由 `win32KeyNames.ts` 在入口转换并拒绝无效名称或重复键；这些名称表示键而非布局相关文本。长文本每 16 个 UTF-16 单元、在完成对应按键释放后让出事件循环，以便处理取消；不能保证单次系统调用被即时中断，也不能保证模拟输入与用户物理按键的系统状态互不影响。隔离 Electron 夹具已验证真实点击、中英文输入以及 `Control+KeyA` 全选并替换；物理 Esc 与生产停止联动尚未验收。

窗口属性代次能使已签发引用在同进程 HWND 被销毁重建后失效；截图完成到属性建立之间以及最终校验到系统派发之间仍存在竞态，它不是 OS 提供的不可伪造实例句柄。同 ID 回执单独持久化在桌面数据目录并在派发前登记，进程中断后的待处理记录保持未知；已完成回执不自动清理，避免过期后同 ID 被当成新动作。

`UiBridge.confirmWithReceipt` 为宿主任务 epoch 提供实际弹窗请求的宿主生成 ID：只有无取消且明确允许的应答才返回 ID，渲染端自报的 ID 不参与判定；既有 `confirm` 仍只返回决定。调度任务身份组件使用该回执，确认入口已用于 Windows 公开桌面操作，单独的回执也不能证明任务归属。

`src/main/desktop/turnEpoch.ts` 是未接线的回合级冲突守卫：续接所绑定的等待记录和当前同意锚点属于不同 epoch 或会话代次时，保留两侧来源并阻止该回合桌面写；同 epoch、同代次仍需重新验证存活，无绑定走首次授权。代次防止归档后重新启用的 Worker 沿用同一会话 ID 时恢复旧授权。批量续接若包含不同绑定也阻止写入，回合结束后解除。身份未知或调用者遗漏未知标记时，守卫同样冻结写入，不能降级成无绑定。它不拦截文本或只读能力；等待记录已绑定宿主来源的武装时 epoch 和代次，归档也递增 Worker 代次，但投递顺序和写操作调用方尚未接入，不能据此宣称冻结已经生效。

`SchedulerDesktopEpochRuntime` 组合宿主确认回执、任务历史和持久审计，等待武装时读取当前有效任务及其确认锚点；没有有效任务返回空绑定。调度清空、新开历史会话和分叉在变更前撤销原代次；删除当前历史会话也先撤销，删除期间若目标后来变为当前会话则在删除后补撤销并报告失败。确认入口已接入 Windows 公开截图工具；重启后的授权不会自动恢复。`test/desktop-continuation-epoch.mjs` 将任务与等待和回合守卫组合，模拟 A 武装、B 回合抢占和下一回合解除；真实续接投递还未连接该守卫。

续接武装时，只有可信身份提供者显式返回 `null` 才表示没有桌面任务；提供者未接入、返回 `undefined` 或读取失败均持久标为身份未知并记录错误。续接来源私有守卫在每次桌面调用时重新核对非空任务绑定及停止代次，身份未知冻结桌面、文本仍可投递。此前创建的空绑定记录无法区分提供者未接入和明确无授权；它们没有新的宿主来源账条目，因此不能用作桌面授权。Worker 等待绑定宿主会话 ID 和持久代次，调度等待绑定当前确认回执或明确的空任务；主入口桌面运行时和写入链路尚未完成接入。

`WorkerDesktopEpochs` 将 Worker 任务绑定到宿主会话 ID、工作区、会话作用域令牌及持久代次；归档前失效以单个 SQLite 事务递增整批代次并使旧读取证明失效。持久写失败时该进程拒绝继续使用该身份。`WorkerDesktopEpochRuntime` 在会话服务启动时注册同步批量前置门，数据库在首次等待或归档时按需打开；失败时相关归档或关闭不会冒充成功。真实 `SessionsService` 夹具覆盖归档、恢复、子树批量回滚和持久存储故障；Windows Worker 桌面工具已接线但真实完整链和续接投递回合守卫仍未验收。

`captureIdentity.ts` 为内部像素读取绑定宿主调用者：Worker 等待 epoch 仍是会话 ID，产物与授权内部键同时包含会话及持久代次的摘要，防止归档后恢复同一 ID 时复用旧截图权限；调度使用宿主确认回执。身份在工作区或会话变化、撤销及取消后失效。该身份组合已接到 Windows 公开截图入口，但跨宿主通道的统一授权尚未完成。

`screenRuntime.ts` 内部组合显示器注册表、任务身份、全显示器读取确认、持久拒绝、产物与审计；调度首次确认创建任务链并覆盖截图范围，已有任务扩展截图范围保留原任务身份。无效参数和未知显示器在确认前拒绝；拒绝后同会话不会因并发重试或重启自动再次询问，拒绝记录写入失败时本进程仍保持拒绝。合成像素和真实 SQLite 的组合测试覆盖了这些路径；Windows 隔离 Electron 另以确认替身调用该组合，获得真实显示器截图、检查持久审计并删除产物。支持匹配显示器的图形会话复用这一整屏截图组合。当前产品入口用可见桌面运行授权覆盖截图读取。浏览器、扩展和 CDP 的统一权限门尚未接入。

Codex GUI 和 Claude GUI 的宿主 MCP 路由可在 `look` 的文字结果之外发送 PNG 图像内容块；调度器 Pi 在当前模型声明支持图片时也可接收该内容块，文本模型保留路径和元数据。图像来自宿主按会话/任务读取并校验的截图字节，不采用模型提供的路径，投递前再次检查截图授权；失败结果不附图。Windows 隔离 Electron 夹具验证了真实截图与图像块字节一致；独立真实 Codex 0.166 / GPT-6.1 Terra 探针用小图和超过 1 MiB 的合成图分别验证模型读出随机数字，未覆盖产品窗口的端到端调用。Codex 会将超限图像事件转换为截断文本，宿主只对可辨认的成功截图事件生成有界摘要，原始工具结果仍按引擎规则交给模型；这一投影不改变引擎自身的历史留存。Claude 路由依据[官方图片尺寸规则](https://platform.claude.com/docs/en/build-with-claude/vision-coordinates)将图片限制在标准模型分辨率及保守的编码大小，并附 `imageView` 与原截图之间的坐标换算；有模拟 MCP 与图片缩放测试，尚无真实 Claude 模型验收。调度器 Pi 仍可能按 SDK 设置缩放图片。GUI Pi 的 `look` 只对当前声明图像输入的非虚拟模型请求 PNG，文本或虚拟模型收到仅有元数据的明确提示；截图须由助手消息直接调用，Pi 嵌套工具路径会绕过结果钩子而被明确拒绝；宿主发送前再次核验回合、连接和截图授权。GUI Pi 校验返回的 PNG 像素尺寸与文字元数据一致，并只对本次截图关闭 Pi 自动缩放；超过模型声明的图片尺寸或编码大小限制时提示缩小截图范围；可关联的工具结果若被扩展改写，进入模型上下文前会替换为错误；扩展本身仍具备运行时权限。已经交给子进程或服务商的数据不能撤回，远端服务仍可能自行处理图片；其他工具和用户附件的缩放设置不受影响。Pi 原生会话 JSONL 会保存工具图片，后续同会话请求仍可能随历史重发，截图文件 TTL 或原回合授权到期不会自动清除原生历史。GUI Pi 在本地模拟模型和受控子进程测试了图片、坐标尺寸、授权失效、文本模型及历史重发，尚未验证真实模型或产品窗口的完整链路。其他 ACP 和 CLI 图像内容块尚未接线。仓库内桌面技能真源已更新，已安装的全局副本需要新版宿主按版本机制同步。

新的 `VisibleScreenGuard` 和 `DesktopActivityRuntime` 为去审批设计提供可见窗口代次、停止按钮、监听失败降级与截图失效组合；提示窗消失后旧截图证明不会因窗口重建而恢复。截图身份同时绑定整个桌面运行租约：单次截图完成后，即使其座位信号已与运行脱钩，停止仍会立即使截图及由其签发的窗口引用失效。`win32TargetRegistry.ts` 从旧控制器拆出共享的截图窗口识别，无需打开旧动作写入器；`win32VisibleRuntime.ts` 将它与新执行桥、Cua 会话、应用发现、共享输入座位及可见提示组合。停止时分别尝试回收语义会话和发现驱动，即使其中一路同步失败也会回收另一路；提示窗等待清理完成，错误会返回调用方。运行时销毁也分别关闭两者。Windows 隔离 Electron 夹具重新验证了独立注册器、真实截图、点击及中英文输入，并确认没有创建旧动作回执库；该夹具的引擎送达仍为模拟。桌面控制路由支持在宿主明确提供该桥时使用它，缺少租约直接报错，不回退旧执行器。`index.ts` 已装配 Windows 可见运行时与 macOS 对应的可见运行时。macOS 和 Windows 都尝试启动各自的 Esc 监听器，失败时继续显示停止按钮。X11 监听器和原生 Wayland 可见停止入口尚未完成产品接线。

`DesktopActivity.flushRendering()` 供宿主等待当前提示窗渲染及其排出的后续更新，渲染失败会抛出；它不确认后端已退出，也不等待之后才发生的状态变化。调用方应先确认停止及后端回收结果，再等待渲染；渲染悬挂时由调用方按自身生命周期处理，不能把超时当作成功。

本次接线采用的 `IdempotentVisibleDispatcher` 复用已有 `DesktopActionIdempotency` 持久回执，不把引擎是否提供“模型已读”事件作为普通桌面操作的前提。同一会话、任务和 `requestId` 不会重复派发；结果保存前再次校验调用方与提示窗，派发后回合失效、后端异常或回执写入失败均报告未知。旧格式回执的参数摘要不兼容时只保证本次不会派发，并提示旧结果可能未知；截图或语义快照失效时也可能在查询回执前被拒绝。换任务、会话或 requestId 不具备语义去重保证，结果输出不证明模型已读取或业务成功。`win32DesktopHost.ts` 将这一回执所有者与 Windows 座位、目标、回合和关闭顺序组合；后端回收无法确认时保留提示与回执资源。Windows 主程序已接线；独立 Electron 夹具已通过真实截图、可见提示、点击、中英文输入与组合键读取，未触发 MetaAgent 桌面确认，也未模拟引擎已读；它不等于真实模型与产品的端到端验证。

Windows 的 Cua 私有 stdio 驱动由宿主包装进程先与现有 Job 监管完成私有挑战和归属，再通过 IPC 接收固定驱动路径与筛选后的环境并启动；宿主或监管进程退出会触发 Job 回收。无操作的 Windows Node 与 Electron Node 夹具覆盖正常关闭、强杀、挑战失败及并发关闭；回收无法确认时报告错误。该验证没有运行真实桌面动作或安装包；macOS/Linux 仍使用既有进程组回收，尚无同等崩溃回收真机证据。

`platformIndicator.ts` 为 Windows、macOS 和 Linux X11 选择 Electron 提示窗，为原生 Wayland 选择 GTK layer-shell 停止控件；未知或冲突的图形会话、缺少 Python 或不支持 layer-shell 时明确报错，不静默回退到 XWayland。Wayland helper 在每个当前输出创建不接收键盘的覆盖层，并在回执前检查窗口与停止按钮已映射、按钮可见、敏感且有非零尺寸；运行中检查映射与心跳，输出变化或 helper 失效会使控件不可用。可注入合成器特定的额外可见性验证，但默认不要求不存在的绝对无遮挡证明：映射和心跳不能保证窗口没有被其他表面遮挡。`DesktopActivityRuntime` 查询可见状态时同步检查控件有效性，失效会中止活动并使旧可见代次失效。平台选择工厂已接入 Windows 与 macOS 主入口。X11 与原生 Wayland 有模拟覆盖，真实合成器与权限行为尚待验收。

Electron 提示窗创建时定位在光标所在显示器工作区的右上角，工作区不足以容纳最小 320×72 的停止控件时明确失败；窗口内容宽度为 400 CSS 像素及以下时切换两行布局，避免状态、提示和停止按钮互相挤出。Windows 隔离 Electron 定向测试覆盖深浅主题、工作区位置、320 像素视口下中英文及停止按钮交互，截图已人工查看；这不等于产品入口或 macOS、Linux X11、原生 Wayland 的真实验收。

Windows 独立 Electron 夹具还串联了真实可见提示窗、显示器截图、截图签发的窗口引用和 `Win32VisibleControl`；自建窗口读回点击与中英文输入，旧审批回调未调用。另一夹具在真实 Windows 钩子运行时确认自身合成 Esc 不触发停止，再点击真实停止按钮，验证在途和排队操作被中断、模拟按住的 F24 已释放。该次为单屏、缩放 1 的受控窗口，送达确认由夹具模拟；物理 Esc、多屏混合 DPI、真实模型识图及产品入口仍未验收。

`desktopResumeState.ts` 为可见运行时提供停止代次 SQLite 存储。主入口在同一 userData 的单实例锁之后调用 `beginRun()`，以 nonce 将本次运行标为 dirty；只有桌面入口关闭且后端停止已确认后才调用 `cleanRun()`。崩溃、强杀、初始化或清理失败都会保留 dirty，下一次启动先递增代次并撤销旧 owner 恢复记录，再提示上次结果未知。停止先同步取消当前输入，再递增持久代次并撤销各会话的恢复记录；停止后只有宿主实际收到的新用户消息能恢复对应 owner。该消息之后由可信桌面回合创建的等待可凭独立来源账在重启后续接；停止前的等待、重试旧消息、未知或修改过的来源不能借新消息恢复。GUI/调度的续接开始、使用和抢占均核对私有来源，排队输入在派发前再次验证；来源失效或存储故障不阻止文本。普通空闲关闭不记为用户停止；状态损坏、写入失败或回滚不明时本进程拒绝继续桌面操作并报告错误。这不证明不同数据目录实例互斥，也不等于 macOS/Linux 真机已验收。

另一个 Windows 夹具经平台工厂使用真实提示窗、停止按钮、Esc 监听器及受控输入：合成 Esc 后运行保持活动；点击停止后在途协作回调和排队回调被中断，测试按键 F24 抬起并由系统状态读回。该测试未模拟物理 Esc，也不能证明钩子实际收到每个合成事件，或任意阻塞原生调用均可中断。

Windows Esc 监听辅助进程监视宿主输入管道；管道 EOF 时向监听线程发送退出消息并卸钩，避免一般的宿主断开后继续驻留。Windows 上以真实辅助进程验证过关闭管道及强杀独立 Node 监管进程后辅助进程退出，测试持有目标进程句柄以避免 PID 复用误判，也没有注入或读取键盘事件；尚未在完整 Electron 产品中验证所有句柄继承情形。

`VisibleSchedulerEpochs` 是尚未启用的调度器身份适配：仅在提示窗处于宿主记录的可见代次时建立任务身份，无须审批回执；同一会话代次的身份在提示窗关闭和宿主重启后保持稳定，避免借此绕过未解决的动作记录。`continuationBinding` 只对已在持久历史中登记且代次未撤销的确定性身份做只读回查，供可信续接比对，不创建活动任务或授予截图许可；实际观察和输入仍须经过可见运行时。关闭会话递增持久代次，写入失败则拒绝后续使用。真实 SQLite 组合测试覆盖调度等待武装、重启后来源校验及代次撤销，模型和提示窗为夹具；主入口尚未注入该只读回查。旧审批链的历史任务与新身份如何共同阻止未解决的旧动作仍需在生产切换时处理，不能只凭此组件声称迁移已完成。

`win32SemanticTarget.ts` 可将已有截图签发的 Windows 窗口选择转换为 Cua 原型需要的宿主内部目标，继续检查会话、任务、进程、窗口代次与几何；模型不能提交原生句柄。它拒绝无法安全转换为 JavaScript 整数的句柄，且尚未接到公开语义接口。macOS/X11 的现有清单还不能认证窗口实例，不能照搬这条路径。

Cua 原型通过驱动实际工具 schema 确认 `set_value` 的投递方式；若该动作缺失或模式不受支持，语义观察仍可使用，并返回 `semantic_set_value_unavailable`，不派发该动作。驱动连接或工具列表读取失败仍按错误处理。调用方提供桌面运行的 `lifetimeSignal` 时，即使一次语义观察已经返回，停止也会立即撤销该会话并回收其辅助进程；该信号仍需由生产桥实际传入。工具 schema 和宿主路由已支持按捕获窗口请求 `semantic`/`both`、快照分页和语义 `click`/`set_value`；Windows 新桥还支持双击及横向滚动。产品尚未组装这些后端，当前语义请求返回 `capability_unsupported`，双击与横向滚动明确报后端未就绪。

`cuaDriverPath.ts` 按宿主提供的开发目录或安装资源目录、平台和架构定位固定的 Cua 可执行文件；缺失时分别给出准备或修复安装的提示，拒绝最终驱动目录或可执行文件是链接，并在 Unix 要求可执行权限。它不单独验证全部伴随文件的哈希或签名，也尚未接入产品；六组路径以模拟文件验证，Windows x64 开发缓存通过定位器启动真实驱动并完成 `list_apps`，Unix 权限和实际安装路径未在 Unix 真机验证。

`VisibleActionDispatcher` 将现有请求去重存储与新的可见动作持久屏障组合；同一请求可在重启后取回结果而不重新派发，未知或未确认结果会阻止该任务的新写入。返回前在任务锁下核对去重记录、outbox 结果与送达凭据，防止损坏的副本冒充结果。供宿主确认送达的凭据仅保存在宿主侧，序列化工具响应不会包含它；协调器本身不能判断引擎是否真的收到结果，可信送达事件和未决动作恢复仍须接线。`DesktopTurns` 提供独立的回合级送达租约：单次输入结束后其座位信号可能不再随 Esc 中止，迟到确认应检查回合租约及提示窗代次；语义驱动关闭后的临时会话也不能作为送达租约。

`GlobalDesktopWriteBarrier` 和 `GlobalVisibleActionDispatcher` 是尚未接入产品的跨任务写屏障及独立派发器，所有受保护入口必须共用同一可信存储根和锁。动作派发前持久记录，全局未确认或未知结果阻止其他任务继续写；不同请求的第二个动作因已有记录被阻挡、且自身事务已回滚并释放锁时，返回普通未派发失败，不中断第一个动作的送达确认。自身持久化或锁状态不明仍需恢复。超时后若后端未停止仍持锁；解除未知状态阻塞须待原执行器结束、锁安全释放，并经宿主独立核验结果，或由真实用户在知晓结果未知后明确指示继续。派发器不嵌套旧任务 outbox，公开请求 ID 由宿主映射为稳定的逻辑操作 ID：不同任务可复用同一公开 ID，同一操作跨任务续接必须保留原逻辑 ID，但不能凭新的会话或任务冒认原请求的作用域。送达令牌保留在宿主闭包，确认还需宿主读取并独立验证同一操作的真实引擎送达证据。Codex GUI、GUI Pi 和调度 Pi 的宿主构造点已支持从同一个 `AppContext.desktopEngineDelivery` 接收私有证据能力，配置工厂无效时不会静默回退；`index.ts` 仍未创建和注入 vault，所有写入入口及旧执行者排除也尚未接线。重启后只保留结果及令牌摘要，未确认动作继续阻塞且不会重放，但无法从该存储重取原回复或令牌。

尚未接入产品的 `desktopActionAuthority.ts` 将会话、任务及公开请求 ID 映射为宿主作用域内的逻辑操作 ID，并严格分类后端结果：Windows 仅接受规定形状的已派发且效果不可验证回执，Cua 仅接受规定形状的效果已确认、不可验证、拒绝或未应用回执；部分执行、疑似无效、未知及意外形状均保守视为未知。已知回执可以持久化不代表应用中的业务效果已验证。

`acknowledgeUnknown` 是尚未连接用户界面或宿主事件的后端能力：宿主注入的验证器必须独立核验不可由模型构造的用户事件，证明用户知晓该精确标记结果未知且明确指示继续；普通新任务、模型文本或工具参数不足以授权。原执行器停止、全局锁成功释放后，事务再次检查当前性及事件与标记的绑定，再将历史写为 `acknowledged-unknown` 并删除阻塞标记；它不判断旧动作成功或失败，旧请求仍只返回 `unknown` 且不重派。同一用户事件摘要只能用于一个标记；结果哈希可保留但不转为送达或效果证明。v2 存储为完整历史维护计数与摘要，检测记录丢失或篡改；它不是对有权限同时重写数据库和摘要者的签名。每次读取会线性复核历史；Windows 本机 Node 对 1 万条合成终态记录的单次读取为 125–156ms，真实操作会多次读取，尚无完整产品性能基准或归档策略。v1 升级在单事务中保留既有标记及历史，要求宿主持有可信迁移排他证明：旧版执行器已停止且不会重启，未配置证明则拒绝迁移。迁移前 v1 已缺失的历史无法由新摘要找回。当前没有生产用户事件验证器、迁移排他接线或 UI，不能据此声称用户已能执行该恢复。

在途、未确认、已确认或已核对的相同请求，按原会话、任务、目标、动作、公开 ID 和参数摘要核对后返回 `unknown`，不重复派发或生成送达凭据；同一逻辑 ID 的参数或作用域变化会明确拒绝。只读查询可在原后端持锁期间执行，写锁获取后还会在 SQLite 写事务中再次检查；初次查询后遇到明确的锁竞争时，会再次读取并核对已提交记录。首个写入已取得文件锁但尚未提交标记时，另一调用尚无记录可核对，遇到占锁会报告普通未派发失败。派发器以宿主进程内私有身份标记已经核对的只读查回，并经 Windows、Cua 投影及 GUI/调度活动包装传递；经过核对的重复请求只返回 `unknown`，不会再次派发或停止首个等待送达的动作，普通同文案的未知结果仍触发停止。该身份不能由工具响应文本或复制结果伪造。Cua 和 Windows 的目标引用或语义快照过期或不可用时，重试仍可能在记录查询之前被拒绝，因此不能声称产品调用已完整满足重复请求恢复合同。旧 Windows 回执采用不同参数摘要格式，当前只能阻止重放，不能声称已核对其参数或重取原回执。

全局切换可用 `previewLegacy` 检查旧派发、锁、回执和全部宿主枚举的 outbox，生成摘要、已知派发及启动的数量，不修改旧记录；旧回执无法还原具体应用或动作。激活时宿主必须持有跨进程旧写入互斥，证明旧写入及旧自动续接已排空并永久排除，并重新扫描和核验完整性；旧动作待定、未知、损坏、残留锁、未解决 outbox 及无法识别的回执格式继续阻断，需保留原记录并只读核对。源码已知且严格完成的旧 Windows 派发和启动回执自动导入为“送达未核实”，不要求用户针对清单或摘要另行确认，也不生成虚假的授权或送达证明。旧 `[sessionId, taskId, requestId]` 摘要保留在新存储中用于拒绝重放；停止桌面操作后仍由宿主回合生命周期要求新的用户指令才能恢复，不能仅凭旧回执解除未知结果。组件测试使用真实 SQLite 和 Windows Node 进程，桌面效果、宿主排他承诺及引擎证据为替身；macOS/Linux 真机、实际迁移和产品入口尚未验证。

`cuaVisibleAction.ts` 将语义调用接到持久派发，并要求宿主提供回合租约、窗口有效性和私有送达槽；没有送达槽时在调用驱动前拒绝。`cuaVisibleBridge.ts` 将语义快照绑定到宿主会话、运行周期和窗口引用，禁止把一个窗口的快照用于另一个窗口；它向驱动会话传入运行生命周期信号。语义动作等待驱动异步退出后再次检查调用者、目标和快照有效性，期间失效则返回 `unknown`，不把原先的结果当作确定送达。桥和持久派发尚未在生产组装。Windows Electron 受控夹具已通过真实 Cua 语义观察及前台点击，提示窗处于可见状态，测试窗口独立读回按钮文字变化；驱动将效果报告为 `unverifiable`，送达回执由夹具模拟，未证明真实模型消费、物理 Esc、Cua 已按下输入的中断释放或产品入口可用。

`legacyDesktopMigration.ts` 为切换提供未接线的旧记录检查：检查旧派发标记、动作回执及锁，包含 SQLite WAL；旧动作未知、损坏或残留锁会阻止切换，原记录不会被自动删除。调用方必须先证明旧执行器全部停止并在检查和激活期间保持跨进程互斥；旧结果只有不可逆摘要时无法自动核对，检查也不包含未接入生产的旧通用 outbox。

`codex/toolDelivery.ts` 和 `codex/desktopDelivery.ts` 将候选回执跟踪接入 Codex GUI 的宿主 MCP 网关与 app-server 0.166 回合事件：限定同一线程、回合、服务、工具、参数摘要和完整结果文本，只有宿主持有的动作 ID 匹配时才调用私有确认闭包；支持语义结果和 Windows 可见动作结果两种格式。停止或连接结束会使待确认槽失效。入口处理会等待早到的 `item/completed` 确认结束，再处理本回合完成；进程退出和确认超时独立使租约失效。`desktopDeliverySelector.ts` 和 `desktopDeliveryInvocation.ts` 为桌面桥提供私有引擎作用域及宿主调用绑定，多个作用域同时存在、选中的作用域失效、停止或调用已返回后不降级或复用；该桥尚未接入产品。已用真实 Codex 0.166、模型和网关验证测试专用只读无操作工具的成功事件与匹配；确认闭包为测试替身，并非真实 SQLite 回执。普通未声明只读的 MCP 工具在标准模式会触发 Codex 询问，当前传输层会取消该询问；另用测试专用无操作工具验证了仅对该工具设置 `approval_mode=approve` 可正常送达，尚未对产品桌面工具启用。桌面桥尚未接入产品工具，真实可写工具、断线重连与远端模型消费也未验证。SDK 回退路径没有可信的同等事件，不提供该确认能力。

Codex 桥可选接收宿主私有 `GlobalEngineDelivery`：写屏障结果先经 `GlobalDeliveryEvidenceVault` 暂存和绑定序列化文本，仅在 app-server `item/completed` 通过严格匹配后由 tracker 在确认调用内签发临时证据。网关调用 ID 与原生事件 ID 分别保留，通过唯一候选及携带随机动作 ID 的完整结果关联；事件重放、错误参数或结果、取消及未确认均不会清除全局标记。真实 SQLite、宿主网关与模拟 app-server 组合回归覆盖这些路径；生产尚未注入该依赖，也尚未验证真实 Codex 引擎接收全局写屏障结果。

调度器 Pi 和 GUI Pi 也可由宿主私有注入相同的 `GlobalEngineDelivery`。槽在全局结果落盘后暂存，完整序列化文本匹配后绑定；调度器仅在真实 Pi `turn_end` 匹配后签发证据，GUI 则还需主进程验证受监管子进程的回合代次、调用 ID、私有证明和完整文本摘要。主子进程使用 UTF-16 码元摘要，避免不同的未配对代理项被 UTF-8 替换成相同字节。单动作、并发拦截、停止和结果改写已用真实 Pi、SQLite 及本地模拟模型覆盖；调度器进程在送达前退出后重开存储仍保持阻塞，GUI 另覆盖真实 worker/本地 SSE。产品路径尚未注入这些私有依赖，也未验证远端模型或真实产品窗口。

GUI 和调度器的预备接线在用户提交消息时记录桌面指令代次，附件处理前先固定该代次与目标工作区；排队、后台消息、自动重试和 GUI 手动重试不得把旧内容转成新指令。GUI 手动重试仍可继续文本，但停止后不能因此恢复桌面。调度器插话只有在引擎确认消费原文后才切换桌面回合，输入处理器改写正文而无法关联时保守拒绝。CLI 的预备代码以宿主认证的会话令牌和 PTY 进程代次在 HTTP 请求体读取前捕获身份；新模式要求通过 `Authorization: Bearer` 传会话令牌，单放在请求体中的令牌无法满足预捕获。终端写入成功不等于引擎已消费新指令，CLI 的停止后恢复仍需要可信消费事件。上述新回合守卫尚未通过产品入口启用或真实模型端到端验收。

- `src/main/desktop/runtime.ts` 区分 Windows、macOS、Linux X11 与 Wayland，并在未连接后端时报告不可用及修复提示；检测不弹权限框。Wayland 输入及语义动作的提示说明原生后端和可见停止入口尚未接入；XWayland 只适用于 X11 客户端，不作为原生 Wayland 兜底。
- `src/main/desktop/platformEscapeAvailability.ts` 提供非 Windows 停止能力诊断和 macOS 当前进程的输入监听权限只读预检；授权通过不代表独立 helper 已获授权或监听器正在运行。macOS/X11 已有独立监听原型，但不能可靠区分合成输入；原生 Wayland 监听未实现。该诊断尚未接入产品提示，三种环境仍需真机验证。
- `src/main/desktop/win32Inventory.ts` 是 Windows 只读枚举：读取可见顶层窗口的标题、进程及调用方 DPI 上下文下的矩形；进程身份读取失败、窗口消失、最小化和截断均单独标注。原生句柄可能复用、坐标可能被 DPI 虚拟化，观察不具备可操作身份，不能直接用于输入或截图。
- `src/main/desktop/macInventory.ts` 是 macOS Core Graphics 只读枚举，按屏幕坐标返回当前用户会话的在屏窗口；缺失标题和进程名只标记未知，不能据此推断权限状态。依据 [Apple 的窗口列表合同](https://developer.apple.com/documentation/coregraphics/cgwindowlistcopywindowinfo%28_%3A_%3A%29?language=objc)，窗口字典来自当前会话；窗口和进程实例仍未认证，不能直接用于输入或截图。
- `src/main/desktop/x11Inventory.ts` 是 Linux X11 只读枚举，调用已安装的 `wmctrl`（默认 `/usr/bin/wmctrl`），读取 EWMH 客户端清单与几何，缺依赖或 DISPLAY 时给出原因。该工具使用文本行协议且 PID 由 X11 客户端声明，结果和坐标均不能作授权或操作身份；Wayland 会明确拒绝，不把 XWayland 结果当成原生 Wayland。参数和输出格式参照 [wmctrl 源码](https://github.com/Conservatory/wmctrl/blob/master/main.c)。
- `src/main/desktop/inventoryProjection.ts` 将三平台的观察投影为不透明的仅元数据记录，移除原生句柄，观察投影自身的操作能力返回不可用；观察 ID 不是可授权的窗口 ID。
- `src/main/desktop/inventoryProcess.ts` 与 `inventoryWorker.ts` 是 `host.desktop.list` 使用的独立进程枚举适配；构建时生成 `out/main/desktop/inventory-worker.cjs`。主进程校验平台、单次响应、大小、退出状态及返回结构，超时或取消时请求终止并如实说明退出尚未确认。Windows、macOS、X11 分别调用对应适配，Wayland 和未知图形会话明确拒绝，不把 XWayland 当原生 Wayland。Windows 在系统 Node 和 Electron 内置 Node 运行时分别实测返回只读元数据，macOS/X11 仅模拟参数及错误分支；安装包及其原生模块尚未验证。
- `src/main/desktop/listService.ts` 与 `metadataRuntime.ts` 组成只读列表：`host.desktop.list` 从宿主调用上下文绑定会话和工作区，并为每次元数据读取生成仅供审计的调用标识；它不是桌面任务授权。窗口枚举异常作为明确的部分不可用返回，异步查询结束后再刷新显示器元数据；显示器刷新失败、调用者失效、取消或持久审计失败则整体失败，不披露结果。显示器和窗口分别按偏移分页，每次重新取快照；长名称与限制项有截断标记，单次返回受限以避免宿主结果上限。`metadataFactory.ts` 按需初始化显示器监听、独立枚举进程及 SQLite 审计，应用退出时释放；不触发捕获、激活或输入。Windows 有真实 PTY 与隔离 Electron 组合测试，macOS 和 Linux 尚未实机验证。
- `src/main/desktop/surfaces.ts` 接收可信平台适配器的完整枚举，原子替换对应后端的窗口；适配器必须证明窗口实例身份，不能仅用可能复用的原生句柄。进程或窗口实例变化、窗口消失再出现时生成新身份，位置、大小或缩放变化时更新几何版本。枚举失败不得拿不完整结果替换当前快照。
- `src/main/desktop/captureTransform.ts` 按截图和当前窗口的身份、几何版本及有效期校验坐标换算。
- `src/main/desktop/displayRegistry.ts` 是 Electron 显示器注册表：先订阅增删、几何以及电源休眠/恢复事件再枚举，返回不透明表面身份；捕获前后重新枚举，显示器拔插、复用 ID、几何变化或读取失败使旧身份失效。休眠期间拒绝枚举，休眠和恢复都使旧身份失效，枚举中发生电源状态变动也拒绝结果。Electron 的负数无效/统一桌面 ID 单独计为未覆盖，不能猜测对应采集源。该机制依赖事件连续送达；其他可能漏事件的时期仍须由宿主调用全量失效。生产截图运行时已使用该注册表；[Electron powerMonitor 文档](https://www.electronjs.org/docs/latest/api/power-monitor)定义 suspend/resume 事件。
- `src/main/desktop/captureArtifacts.ts` 是 PNG 截图产物存储：按任务绑定、随机标识、有效期和内容哈希校验；先写元数据以便进程中断后清理。正常记录按 TTL 清理，元数据损坏或丢失时报告异常，并在关联普通文件最后修改至少 24 小时后保守回收；链接、错误路径及无法读取的文件不会被跟随删除。时间被回拨、文件被外部改写或清扫长期未运行时，实际残留会更久。`pngDecoder.ts` 复用项目的 sharp 完整解码并限制像素，存储层要求可信解码器且比对尺寸。`captureCleanup.ts` 已接入应用启动和定期清扫，错误写日志并提示，取消退出不会停止清扫；`sessionCaptureAccess.ts` 将会话专属目录加入 GUI/CLI Worker 和调度的宿主只读范围并拒绝链接重定向，不增加原生 SDK 的可写目录。调度每回合使用稳定目录，设置预览不创建目录。Windows 和 macOS 公开截图使用该存储；上述已接线的引擎路由可附加当前截图的图像块，`captureRead.ts` 历史读取接口尚未公开，不能宣称文本模型已能读取截图路径；引擎自身沙箱的文件读取行为仍以各引擎为准。清理前的同会话历史截图仍可能通过文件层读取，任务级 API 校验是主执行边界。
- `captureRead.ts` 的内部历史读取根据截图元数据的任务摘要查找当前会话的持久任务历史，再核验文件完整性和到期状态；同一会话开启新任务不会抹除旧产物归属，关闭会话或读期间代次变化则拒绝。该路径不接受模型自报任务 ID，调用方仍必须绑定可信会话和审计，公开入口尚未接线。
- `src/main/desktop/displayCapture.ts` 是 Windows 与 macOS 公开工具使用的屏幕截图适配层。Electron 的 `getSources` 一次请求所有显示器的缩略图，先由宿主要求覆盖此范围的授权并审计，再按官方 `display_id` 与显示器 ID 唯一匹配；缺失或重复时拒绝，不根据源名称或次序猜测。可按源截图像素矩形裁剪返回图像，并报告源尺寸与实际裁剪矩形；越界或后端不支持裁剪时明确拒绝，裁剪不缩小底层读取或授权范围。`captureId` 与对应的持久产物 ID 一一对应，可供任务级读取适配器查找；图像尺寸以实际结果为准，取消、几何变化或审计失败时撤回尚未发布的产物。截图适配器声明图像像素坐标，控制组合依据截图区域和显示器几何换算输入坐标。[Electron 源结构](https://www.electronjs.org/docs/latest/api/structures/desktop-capturer-source)和 [PipeWire 限制](https://www.electronjs.org/docs/latest/api/desktop-capturer)是接口依据；Linux portal 选择后仍需能可靠匹配显示器。Windows 独立 Electron 实测获得 1920×1080 图像及 100×80 裁剪并删除临时产物；macOS 隔离 Electron 实测获得单屏 1920×1080 截图。Linux 真机与 portal 尚待验收。
- 截图先转为实际 PNG 字节，再由可信后端解码为单倍率像素图；归一化尺寸必须与 PNG 头一致，随后才按像素裁剪。Windows Electron 的合成 2× 图像回归验证裁剪像素与原 PNG 相同，避免直接对多倍率 `NativeImage` 按逻辑尺寸裁剪；真实多显示器高 DPI、macOS 和 Linux 尚未实测。生产接线必须提供以 PNG 解码创建单倍率图像的实现。
- 可选画面稳定等待在同一授权和审计范围内重复采样，只有连续两次返回图像、源尺寸和区域完全相同时报告 `observed_stable`；到期报告 `timeout` 并返回最后一次采样，取消或表面变化不发布产物。采样仅证明两个采样点一致，不证明业务效果或两点之间没有变化；超时在已完成的采样之间检查，底层采集调用卡住时无法保证严格墙钟截止。Windows Electron 验证过真实采样、尺寸和产物清理，超时及取消由模拟测试覆盖。

调度目录范围的代码和模拟测试覆盖连续回合稳定性与跨工作区拒绝；Windows Electron 全流程两次分别在重启前关闭和最终清理的 `app.close()` 处超时，后一次已执行完用例断言但未完成退出，不能将整项验证记为通过或确定超时原因。
- `src/main/desktop/screenReadAuthority.ts` 与 `screenReadUi.ts` 为内部截图组合提供权限与人工确认：同一会话内的当前任务串行确认所有显示器读取范围，任务变化立即使旧批准及在途确认失效，批准最多 24 小时；拒绝写入持久日志，撤销使在途确认失效，只有人明确要求并通过审计后才可重新考虑。中英文确认披露全部显示器和任务期限；拒绝持久化失败时当前进程仍拒绝，跨重启不能假定已保存。人工重新考虑的产品入口尚未接线。
- `src/main/desktop/displayService.ts` 组合显示器身份、会话授权和截图产物；授权撤销或几何变化发生在采集中时不发布结果。它仍要求调用方注入可信会话/任务身份、审计和产物存储，语义树返回不支持；Windows 公开工具使用该服务，Worker 文件读取仍需真实验证。真实 Windows Electron 测试使用测试替身批准和审计，不代表已验证产品中的人工确认流程。
- `src/main/desktop/semanticRefs.ts` 为单次语义快照签发不透明引用，按窗口实例、语义树版本与有效期验证；缓存有数量和时间上限。Cua 原型使用该机制；真实产品公开接口尚未接入语义后端。
- `src/main/desktop/grants.ts` 保存任务、应用、进程、窗口、动作与不可逆对象范围的内存授权，拒绝超过 24 小时的有效期；调用方仍须接入真实批准和审计。
- `src/main/desktop/schedulerTaskEpoch.ts`、`epochHistory.ts` 与 `schedulerTaskUi.ts` 提供调度任务身份状态机、持久归属及中英文确认文案：首次或显式新建使用宿主确认回执创建 epoch，扩展确认保留当前 epoch；替换不抹除旧产物归属。SQLite 保存同会话历史与会话代次，重开后可校验旧产物归属但不会恢复操作授权；关闭会话递增代次并清理归属，另一个连接的关闭也使活动授权失效。持久化关闭失败时本进程继续拒绝该会话的授权及历史读取。清空、新开历史、分叉、删除当前调度历史和 `waitFor` 绑定已接宿主生命周期；续接投递的写入守卫尚未接线，截图组合已对 Windows 公开工具开放，不得由模型调用显式新建入口。
- `src/main/desktop/authority.ts` 是 Windows 动作使用的审批与审计状态机：复用任务内应用批准及同一具体不可逆操作的对象确认，作用域变化、到期或撤销后不复用；拒绝后不自动重新询问，只有宿主收到用户明确要求并审计后才能清除拒绝。派发前审计失败则拒绝，派发后失败或中断报告未知并阻止该任务继续派发，需宿主独立核对或由人处置并完成审计才能解除。调用方负责绑定真实任务身份、对象分类、窗口实时校验及可取消后端；它本身不能证明任何通道已受控。
- 协调后的桌面和浏览器派发在锁成功释放后才清除持久标记，并在锁释放后及清理标记后再次校验目标与授权。释放异常时保留标记并报告未知，即使锁实际已解除，独立协调器和重启后的实例也会拒绝后续写入；若清除标记的调用结果不确定，或授权在清除期间失效，进程内仍阻止重放并拒绝披露，实际标记可能已删除，跨进程恢复仍需解决。生产调用必须经过协调层，直接调用内部 `DesktopAuthority.run` 不提供此锁释放约束。
- `src/main/desktop/unknownActionChain.ts` 是 Windows 动作使用的未知动作链确认状态机：按任务、应用、动作类及窗口实例、几何代次和截图范围复用批准，同范围的新截图不逐击确认；切换上述范围、任务结束或 24 小时到期后重新确认，旧令牌不会在重新批准后复活。动作门核对请求的进程和窗口代次与证据边界一致。拒绝复用独立的持久记录；重新考虑必须经宿主审计，并与该任务的待处理确认串行化。组件支持由宿主主动通知接管失效，但 Windows 没有接入物理接管检测；跨通道统一审计也尚未接入。
- `src/main/desktop/unknownActionUi.ts` 提供未知动作的本机确认及截图预览：对比宿主截图摘要、采集 ID、应用、进程、窗口代次、几何代次与区域，确认框显示目标应用、动作类和截图区域，图片加载失败不能批准。截图提供者、动作身份与任务生命周期必须由宿主可信绑定；当前函数已接入 Windows 动作后端，真实产品确认界面仍待验收。
- `src/main/desktop/actionEvidence.ts` 是 Windows 动作使用的有界内存证据注册表：复制并解码宿主采集字节，按会话、任务、采集 ID 和窗口身份核对，每次动作返回可复查的有效性证明，关闭会话使在途注册和证明失效。容量上限 32 项、80 MiB，满时明确拒绝；清理会清零已移除的内部字节。调用者必须在任务生命周期及定时清理时调用清理入口，注入完整 PNG 解码器，并确保只有可信采集后端能注册；重启后不恢复这份操作证据，已保存的截图产物另按其自身规则管理。
- `src/main/desktop/auditStore.ts` 是持久审计存储：`host.desktop.list` 的默认元数据路径及 Windows、macOS 公开截图已接线；可选应用发现路径尚未接入。它只接受宿主固定来源、动作、阶段和结果，拒绝附加字段与自由文本；会话、任务、应用和窗口身份以摘要记录，截图与不可逆对象只留摘要。SQLite 写入失败时调用者必须拒绝披露或派发。摘要用于关联而非加密，审计读取、清理策略及浏览器、扩展、CDP 的统一接线尚未实现。
- `src/main/desktop/actionGate.ts` 是 Windows 动作使用的组合门：可信分类动作和未知动作共用任务串行队列及跨进程锁；未知动作先检查未知派发记录，再要求宿主验证每次尝试的证据并提供可同步复查的有效性证明，之后经链确认、任务应用授权和持久派发日志，每次尝试记录证据摘要。授权复用不跳过证据验证；证据失效会阻止派发，派发后出错可能产生未知结果，须核对才能继续。Windows 目前没有接入用户物理接管检测，动作期间用户物理输入可能穿插；按裁决后置，截图授权的跨进程撤销也尚未协调。
- `src/main/desktop/mediatedBrowserPolicy.ts` 是待接线的浏览器动作分类。按宿主展开后的动作名标记内容/像素读取、未知副作用、目标范围和必要清理，映射到固定审计动作名。页面任意 JS 可读像素和改变页面，元素或整页截图会触发滚动，指针移动归 `hover`。录制停止先清理再检查结果的披露授权。Cookie 和下载使用共享 profile 范围。未知动作拒绝分类。审批和执行仍由各工具现行入口管理。
- `src/main/desktop/mediatedBrowserGate.ts` 是内部组合，尚未注册到生产通道：它使用宿主注入的可信会话、目标与授权证明，对参数取不可变快照，并在派发前后校验和审计。可能产生副作用的动作及录制启停共用任务锁与持久派发标记；结果未知时禁止继续写入，保留只读回查和录制取消。只有宿主独立核实或人明确处置、完成固定标签审计后才可核对并清除浏览器标记；其他桌面表面的标记不可由浏览器清除。桌面和浏览器各自必须提供 `DesktopUnknownState`；宿主组合仍必须保证两者使用同一个实例以及同一任务锁和日志，构造器不能证明实例相同。核对只能清除对应标记的进程内状态；桌面核对不得处理浏览器标记。录制清理必须由宿主绑定且可重复执行，失败显式报告；目标或会话已无法可信绑定时，生命周期管理仍须处理遗留录制。统一权限状态、生产通道及生命周期尚未接线，不能据此声称浏览器受保护。
- 浏览器服务预备的内部目标身份绑定已挂载 guest、进程、工作区、所属会话、HTTP(S) 来源和文档代次；导航、崩溃、进程或归属变化使旧身份失效，URL 查询串不进入应用身份。含子框架的页面暂时明确拒绝此身份，尚未提供 iframe 感知授权，不能因此宣称网页能力已完成；该身份和浏览器事件路径目前只有模拟测试。事件含义参照 [Electron webContents](https://www.electronjs.org/docs/latest/api/web-contents) 和 [webFrameMain](https://www.electronjs.org/docs/latest/api/web-frame-main)。
- `src/main/desktop/taskLock.ts` 使用任务哈希的排他文件实现跨进程互斥，允许只读诊断但绝不根据 PID 或时间自动判定锁已失效。进程崩溃或释放失败会保留锁，待宿主确认所有相关协调者停止并人工核对后恢复；恢复入口和宿主生命周期尚未接线。Windows 上有真实双 Node 进程与崩溃回归，macOS/Linux 仅代码与模拟覆盖。

- 桌面宿主初始化失败时，只有在宿主从未构造或已确认完成清理时才清除本次运行标记；清理不确定时保留脏标记，由下一次启动继续按未知结果处理，避免把原生输入状态误报为安全。
- `src/main/desktop/dispatchJournal.ts` 在派发前以排他文件写入并同步任务标记；成功审计后清除，异常或重启保留待核对。记录不包含输入内容；损坏或无法读取时拒绝继续。同进程禁止对在途动作提前对账，多进程恢复仍须宿主确认原进程已停止后才调用对账入口。
- `src/main/desktop/writeOutbox.ts` 是尚未接入生产执行器或续接上下文的通用写操作回执存储。宿主创建调用 ID，先持久标记派发，再记录已知结果或未知结果；同一 ID 不可再次派发，结果和确认支持幂等重试。已交付记录至少保留 24 小时；未交付、损坏或尚未核对的未知记录不清理。未交付结果阻止该任务后续写入；未知结果即使已交付仍阻止写入，宿主必须先独立核验或获得人工决定并记录审计，才能登记核对。按会话分页读取；恢复并把中断状态定为未知前，宿主必须确认原执行器已停止。结果按原样持久化，读取与恢复披露须重新验证可信会话、任务与授权；接线时须限定访问和数据保留。此组件不会自动投递、确认或阻止使用新 ID 重新发起的语义相同动作；检查任务阻塞须与派发共用锁，恢复注入、各执行入口与生命周期仍须接入验证，现有派发标记也尚未被替换。
- `src/main/desktop/outboxedAction.ts` 是未暴露的桌面动作组合：共享任务锁内先检查宿主注入的回合 epoch 与未交付或未知记录，再授权并创建调用记录，持久化期间或结果写入时授权失效、用户接管则不披露结果。阻塞检查在新派发标记之前完成，避免把未执行的新动作误记为未知。结果写入期间失效时已知结果仍留在未交付记录中，阻止下一次写入；恢复读取前须重新验证授权。epoch 校验器是必需的可信宿主依赖，测试组合过续接守卫，真实运行时尚未接线。只有所有入口共用同一个锁、状态和回执存储时才具备这些约束，当前尚未接入宿主生命周期、消费确认或真实桌面输入后端。
- 回执结果只接受可无损序列化的有界 JSON 值；日期、Map、稀疏数组、非有限数、负零、循环或共享引用等被拒绝，派发结果不能落盘时继续按未知处理。调用适配器须自行把二进制及其他结果转换为明确的 JSON 合同，不能依赖隐式转换。
- `src/main/agentSession/piToolDelivery.ts` 直接订阅宿主拥有的 Pi agent，在 `turn_end` 核对原始工具调用、完整文本、同一结果在引擎状态中的对象与当前回合信号，再通过仅宿主持有的闭包确认持久回执；不以较早的 `tool_execution_end`、函数返回或模型自述确认。`schedulerPiDelivery.ts` 已接入调度器 Pi 会话的工具执行与结果序列化；GUI Pi 则由 `drivers/pi/desktopDelivery.ts` 在主进程网关执行作用域保存语义及 Windows 可见动作的确认闭包，通过受监管子进程 IPC 发送一次性私有证明，`childDesktopDelivery.ts` 在实际 Pi agent 接收完整文本后返回证明和文本摘要，主进程与原始序列化文本比对。证明不进入模型文本或展示事件。两者均要求原回合、桌面运行租约、提示窗代次和目标实例仍有效；重复调用 ID、结果改写、截断、丢失、中止、断线或进程回收均不确认，确认期间退出或超时使租约失效。中断和确认失败后须检查持久状态，不重放动作。单次输入的 seat 信号在调用结束后不再跟随运行停止，语义会话信号在成功回收时即失效，两者均不能代替回合租约。跨进程离线夹具覆盖真实 Pi AgentSession、宿主网关和 SQLite 持久屏障；另一夹具以本地模拟模型服务串联实际 workerHost、打包的 Pi worker、语义桥与持久回执。此处证明引擎接收，不证明远端模型消费。产品桌面入口尚未接入语义桥和这些私有槽，其他引擎仍需各自接线和验证。
- `src/main/desktop/inputSeat.ts` 提供协作式输入互斥、速率控制与用户接管取消；真实适配器须响应取消信号并释放按键。接管或动作收尾时释放失败（包括同步抛错）会保留暂停状态，后续动作及恢复不能假定输入已释放。

宿主中介通道共用权限与审计是目标，目前尚未完成接入；授权在内存中，拒绝及派发标记有独立进程退出后的恢复测试，但真实宿主生命周期与多进程对账尚未接入，已按功能先行裁决开放 Windows 写入，相关缺口必须在交付中明确。完整权限 CLI 和第三方 MCP 位于该强保证之外。Windows 在本机系统 Node 和 Electron 内置 Node 子进程实测只读枚举，并有模拟错误路径测试；隔离 Electron 以确认替身验证了原生操作，PTY Worker 端到端测试通过真实产品确认框；安装包尚未验收。Linux X11 和 macOS 枚举仅有模拟测试，原生 Wayland 后端尚未实现，三者均未实机验证。现有只读枚举仍在子进程；新 Windows 控制 FFI 在主进程执行，原生崩溃可能影响工作台，ABI 和崩溃恢复尚未验证。

Wayland 的 [RemoteDesktop portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.RemoteDesktop.html) 管理用户授权后的远程输入设备和会话；[InputCapture portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.InputCapture.html) 按区域边界和会话机制捕获输入。后者不能直接作为对桌面上所有用户输入的被动监测证明，实际能否满足即时接管需另行验证；缺少可信监测时不能开放声称支持接管保护的输入路径。

Windows 的 [低级鼠标 Hook](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc) 和 [低级键盘 Hook](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc) 超时后可能被系统静默移除，应用无法直接获知；仅凭注册成功不能证明之后仍能监测用户接管。微软建议考虑 [Raw Input](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-raw-input)，但它的覆盖、消息队列延迟、输入来源区分和失效检测仍须为本功能验证；在这些边界及原生后端验证完成前不开放声称具备即时接管保护的输入路径。

macOS 的 [CGEventTapCreate](https://developer.apple.com/documentation/coregraphics/cgevent/tapcreate%28tap%3Aplace%3Aoptions%3Aeventsofinterest%3Acallback%3Auserinfo%3A%29?language=objc) 可能因权限而移除请求监听的部分事件类型；创建成功不等于键鼠事件均获许可。[CGEventTapEnable](https://developer.apple.com/documentation/coregraphics/cgevent/tapenable%28tap%3Aenable%3A%29?language=objc) 还规定监听无响应或被用户停用时会发送停用事件。需要分别验证输入监测权限、事件类型覆盖和停用后的安全行为；当前没有 macOS 监听后端或真机验证。

任意原生应用的坐标点击和通用语义动作缺少可证明的不可逆操作分类来源：截图和模型自报不能证明收件人、金额或动作效果。未知动作按链边界人工确认和证据审计处理；对象级强保证仅适用于已适配的语义面。不能把当前 gate 的 `effect` 参数或未接线状态机当作已经解决的强保证。
