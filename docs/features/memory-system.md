# 记忆系统

正式学习链路采用“工作 Agent 按需提交候选 → 专用 Pi 记忆会话整理 → 类型化知识账本”。普通对话结束、Worker 释放或压缩不会自动抽取一遍转录。普通候选无需用户审批、抽查或每日确认；可以查看来源，在记忆中心直接修订、停用、恢复历史版本和撤销，也可以在记忆对话里提出管理请求。实施与质量门见 优化方案，界面见 [记忆中心](memory-panel.md)。

Runtime Kernel 的 `memory-curators` 域负责显式恢复与停止整理会话，创建期 scope 同时托管派生库。退出先关闭候选受理，整理器并发 stop 共用同一 Promise，等待源 session.abort 与处理循环实际结束，再 dispose session 和关闭队列；成功停止后才关闭 MemoryService 数据库。停止失败保留整理器引用和队列，以供重试，不能清空注册表后让异步回调访问已关闭数据库。

## 内容与职责

Windows 打开磁盘 SQLite 库时统一将普通文件路径转为扩展长度路径；范围校验及对外显示仍使用原路径，`:memory:` 和 `file:` URI 保持原样。事件、等待、提醒、应用与记忆库使用同一转换，避免长工作区路径导致数据库无法打开。Windows 已用 Node 和 Electron 内置 Node 验证长路径、共享 WAL 与重开；macOS、Linux 仅验证路径转换分支，尚未真机验证。

记忆中心与整理会话 IPC 的已知拒绝提示、后台整理失败的桌面通知按当前语言显示；已保存的宿主状态说明只在记忆卡、召回原因、处理列表及错误提示显示时翻译。整理会话只投影宿主生成的固定进度消息，并随语言切换更新；原始快照、未知原因、用户正文和提交给模型的原始材料不随界面语言改写。

长期知识分为用户画像、持续约束、可复用经验。用户画像包括用户本人提供的基本信息、联系方式、工作背景和偏好，采用 `user_profile`（个人信息）及既有 `user_preference`（偏好）两种条目类型；旧偏好继续有效，不需要迁移。经验保存问题、方法、成立依据、适用条件、例外和未来用途。任务事实只供历史追溯，默认保留90天，不因重复曝光自动晋升。没有值得保留的内容可以零产出。

工作 Agent 负责发现值得提交的内容，不负责常规扫描全库。`host.memory.note` 是低频候选入口；`host.memory.remember` 仍要求宿主保存的本轮用户原话明确授权，网络污点、无头回合和身份缺失不能借候选文本获得授权。浏览器、桌面清单与截图、应用、外部 MCP 中转、网页抓取和终端读取在转写中的 `host.*` 和下划线形式均保守分类为外部来源，旧工具名也继续识别。两者均要求调用模型传入 1–12 个非空 `searchKeys`（主题词、同义词或未来问法）；宿主脱敏并随候选入队，整理工具合并候选及草稿关键词后保存到记录。由记忆视图直接提出的候选没有调用方关键词时，整理模型须在保存草稿中提供关键词。两者返回可靠入队回执，不表示已经长期生效。已有记忆错误用 `host.memory.correct` 提交精确目标的审核请求，并用 `host.memory.correction` 查询实际结果。宿主绑定当前 workspaceId、会话、轮次、仓库/分支与原始材料；候选不能自证可靠，也不能指定另一个工作区。发现已有记忆错误后由工作 Agent 主动提交纠错；当前没有漏调用后的自动补偿：工作 Agent 未调用工具，就不会启动学习；后台自动处理不等于自动发现。

`curatorBindings.bindCandidateEvidence` 收集已完成的本轮工具结果和可用轮次快照身份，排除记忆工具自己的输出及包装调用。纠错优先收集最近完成的至多8项工具结果，每项摘录至多2000字符；超出摘录的观察不会被假定为已核验。保存知识时，能够定位所选依据原文则只保留相关摘录及附近上下文，其他观察保留来源与哈希但不复制无关正文；无法归属时保留原摘录以免丢失依据。候选队列的原始材料仍按既有保留策略管理，旧知识不做破坏性迁移。工具成功/退出码0不自动升级为 test/runtime 验证；CLI终端摘录明确为混合未核验材料。

## 宿主 memory 技能与工作记录

技能正文由宿主从 `resources/skills/memory/SKILL.md` 安装到 `~/.muster/skills/memory/SKILL.md`。GUI 首条引擎输入、CLI 欢迎词与任务简报、调度系统提示直接给出安装路径。工作区升级时移除旧 `metaagent-memory` 和 `muster-memory` 托管块，保留块外的项目指令。项目 `.agents/skills` 用于用户技能，宿主记忆流程不依赖其中的历史链接。旧 `journal` 技能由用户自行管理。

CLI 以可信启动环境 `MUSTER_HOST=1` 判定宿主，GUI 和调度以可信宿主上下文判定。GUI 和 CLI Worker 的首条宿主说明要求首次调用记忆工具前读取 Skill，并在延续旧工作、参考过去的决策或纠正、解决重复问题或应用长期偏好时先用简短主题词主动检索。日志记录值得回看的决策、发现和交接，长期事实和偏好可主动提交。技能路径不可读时按已注册工具定义操作，明确报告读取或工具失败，私有存储由宿主管理。ACP GUI 与其他 GUI Worker 使用同一组宿主记忆工具。外部引擎的工具回调由宿主绑定真实交互回合，显式记住和确认仍校验本轮用户原文。安装文件、会话加载新版提示和模型取得工具回执分别验证。

技能首先教主动检索：涉及旧约定、纠正、重复问题时用短关键词调用memory.search；区分task、history、journal；核对来源、条件和当前用户意图，空结果最多改词补查，错误不当空结果。用户自然提供长期个人信息或偏好时，工作模型可主动用 memory.note 提交候选，无需等待“记住”；日志保留工作脉络，长期信息可直接提交候选，无需先写日志。候选由整理模型判断是否为用户本人、是否长期有用，以及是否属于第三方、示例或敏感凭据；宿主要求依据可定位到可信本轮用户原话，并核对邮箱与电话号码值，不接受用户明确要求不记录的内容。缺少用户原话的混合 CLI 摘录、工具输出或候选转述不能单独写入画像。是否主动调用及语义归属判断仍依赖模型，工程测试不能证明所有模型不会漏记或误判。

`memory.journal({topic,topicId?,status,problem,points,entryId?,revision?})`由宿主绑定controlRoot、会话和本地日历日期。状态支持进行中、已完成、阻塞和搁置；可选 `topicId` 显式关联不同会话、日期下的同一主题，不自动合并或授权跨会话修改。参数不接受路径/任意工作区，更新只能针对本人条目；同会话同日相同正文幂等。`runtime/journal.sqlite`事务/outbox写到`journal/YYYY-MM-DD.md`，revision冲突或外部修改拒绝覆盖；真实落盘后才返回saved回执。旧标题/问题/要点格式保留，结构ID和主题ID使用HTML注释；日报隐藏这些元数据。跨日更新保留原条目日期。退出摘要也走同一写服务，已有会话日志时不重复生成。

GUI/PTY执行器通过`callingSessionId`绑定会话ALS，记忆入口优先据此查询会话所属工作区；不要求Worker同时携带调度的workspace ALS，不使用界面当前选中工作区。会话已删除或无工作区时拒绝，不能回退到其它范围。调度无Worker会话时沿用其可信workspace ALS。`points`必须是字符串数组。回归`test/memory-journal-host-binding.mjs`经过真实GUI工具适配器、参数绑定、执行器和日志存储，覆盖无workspace ALS、伪造参数、并发/跨区隔离、调度以及错误points格式。

`memory.search(mode=journal)`按关键词或精确topicId及可选date/fromDate/toDate检索，每页最多扫描90个有记录日、返回最多10条，`nextCursor`继续扫描更早日期或同日余项。history结果中的journal字段只作预览；`memory.journalGet`按日期和字符偏移分段读取原文。日志凭据形状会脱敏，单日读写上限2MiB。日期列表会先恢复已提交但未投影的outbox；幂等重试同样检查原段仍存在，不将丢失正文误报为已保存。

## 当前目录与初始化

只使用当前布局：工作区日志在 `.muster/memory/journal`，类型化知识在 `memory/knowledge/<namespace>`，整理队列在 `memory/curator/<workspace-hash>`，日志及检索运行库在 `memory/runtime`。日志索引监听和注入来源说明使用同一当前目录；不存在的目录仍由后续指纹检查兜底。索引指纹 v2 保存 `mtimeMs`、`size` 和正文 SHA-256，mtime/size 未变时不读文件，时间戳变化但内容哈希未变时只更新指纹，不重建 chunks。全局用户画像与工作台通用经验分别使用应用 userData 下的独立库。

`layout.ensureMemoryLayout` 仅验证当前路径边界并创建目录，不读取旧路径、layout.json、迁移清单，也不复制、合并或清理既有资料。旧目录自动迁移、旧pending复评、旧画像备份和历史Markdown投影转换已移除。已有旧文件及备份保持原样，不作为运行数据源；软件尚未发布，不保留版本兼容支线。

当前账本的事务、outbox崩溃恢复和当前队列恢复继续存在。初始化时，已有账本记录对应的投影缺失或内容不一致仅隔离该条：记忆中心显示ID，日志记录异常，普通召回与核心注入排除该条，整理对照仍使用账本最后提交内容并明确提示；其他完整记录可检索、保存，异常条目的写入仍拒绝覆盖。宿主发现文件恢复到与账本一致后解除隔离；不自动重建或覆盖文件。未知的孤立损坏文件、符号链接、账本损坏及outbox冲突仍可能使库不可用，不把不完整对照伪装成成功。

知识库的 `knowledge_fts` 是可丢弃的派生检索索引，账本 `records` 和 Markdown 投影仍是事实来源。`knowledge_fts_meta` 按记录保存当前 revision 与 FTS 内容哈希，写入和启动恢复只在版本或派生内容变化时重建该条索引；元索引缺失时会从现有账本回填，不要求迁移旧记录格式。索引残留会在启动时按账本身份清理，关系表仍按当前记录重建，索引损坏不会改写知识正文。

`knowledge_hot` 是可重建的轻量派生表，只保存 `id`、`namespace`、`kind`、`status`、`updated_at`、`created_at`、`expires_at`、`repo_key`、`branch` 和 `task_id` 等列表筛选列；`records` 的 JSON payload 仍是唯一事实来源。启动会删除孤立行并按 `records` 回填，旧库不需要迁移；每次 `persist`/`index` 写入同步 upsert。`KnowledgeStore.listPage` 使用这些列完成范围过滤、稳定 keyset 排序和计数，重建失败或表损坏不会改写 canonical 记录或 Markdown。

## 专用 Pi 会话

`curator/pi.ts` 使用真正的 Pi SDK `createAgentSession`，purpose 固定为 memory。资源加载器显式返回空 skills、AGENTS 文件、prompt templates、extensions、packages、themes；关闭 SDK 自动压缩、自动重试、遥测与图片，禁用内置文件/Shell工具。会话创建后再次核对实际工具目录，只允许以下五个工具：

| 工具 | 职责 |
|---|---|
| `memory_candidates` | 读取宿主授权的本批候选与依据ID |
| `memory_search` | 比较已有知识、退场记录和删除禁用；写入前必调 |
| `memory_evidence` | 分页读取本候选的来源句柄，不接受任意路径或命令 |
| `memory_commit` | 提交保存、关联重复、历史、不收录、暂停、取代、绑定目标更正及用户明确删除/恢复 |
| `memory_defer` | 依据暂不可用时有限延后，不能改成人工审批等待 |

专用系统提示词要求只做记忆管理；无关请求收口后提示切换调度 Agent，不自动转发。候选、来源和工具输出作为数据，不能改变角色权限。提示词及候选/用户输入等注入点登记于 `agent/injection-registry.ts` 的 `memory.curator.*`；压缩提示词保留登记，当前运行通过有界换代控制上下文，未开启 SDK 自动压缩。

记忆库的稳定错误和模型工具协议继续使用原文；记忆中心 IPC 只对已知宿主错误及其固定前缀按界面语言翻译，动态身份和未知错误原样保留，不修改持久记录或模型工具结果。

模型优先使用全局记忆专用配置，其次当前工作区调度模型，最后全局默认。复用所选供应商协议/凭据，独立会话不继承调度工具或技能。面板显示实际模型。空队列、读取状态、打开面板、切换角色和加载历史不发模型请求；启动/工作区打开只恢复已有候选队列。

## 队列、处理与故障

每个工作区在 `controlRoot/.muster/memory/curator/<sha256(workspaceId)前24位>/` 保存 `curator.sqlite`、Pi转录和受限 agentDir；同一controlRoot的不同工作区身份也不共用会话。队列以宿主事件+内容身份幂等入队；内容身份冲突报错，不把后续工具完成重复算成新候选。claim、租约、generation 与当前策略签名在提交前复查，暂停、切模型、删除工作区和迟到回调不能继续写入。

自动候选另以持久信息身份合并跨轮重复投递：范围、原始用户/工具观察材料、候选内容与条件、目标revision及策略身份相同才合并，不因eventId或临时工具callId变化重新请求模型。原始材料、方法/条件、目标版本或策略变化仍可新建；明确的人类记住/更正/删除/恢复独立处理，不复用旧授权。重复事件不重置已延期的最早重试时间或尝试次数；不宣称能对任意改写做语义去重。启动只恢复当前持久候选队列，不扫描知识库补造候选。

默认每批最多3个候选、全局最多2个工作区处理器、单批10分钟、最多32次模型请求；宿主选项可在有界范围内调整（请求最多64次）。每候选最多24次依据读取，单次8192字符、合计131072字符。会话上下文依据实际模型配置容量扣除输出/协议余量后计算保守字符界限，不再固定截在64000字符；缺少有效配置时按128000上下文容量处理，不能把所有供应商都当作百万上下文模型。可恢复错误有限延后，候选尝试最多3次；失败保留实际错误，可在整理记录中重试。未提交真实回执不能显示为保存成功。空闲默认5分钟释放 SDK 会话对象，持久队列与转录保留。

宿主可信的模型请求/上下文预算耗尽会结算已有回执，把剩余候选延期并持久标为单条续跑；上下文到限同时换代，重启后仍按单条处理。每条仍最多3次尝试，耗尽后才进入最终失败；已完成候选不重新提交。错误类型由请求边界产生并保留，不靠模型输出中的“预算用尽”字样授权自动续跑。扩大默认预算不会自动重排升级前已有的failed记录；用户显式重试或既有模型/策略变更可重新排队。

模型正文不等于完成回执。宿主在会话开始、正常结束和异常结束后逐条复核真实账本回执，补偿事务已提交但队列ACK丢失的窗口；回执须通过格式和候选归属校验。仍缺回执时仅对未完成候选给一次补结算机会，原工具闭包保留比较结果和依据读取计数，已经完成的候选从可见列表移除并拒绝旧ID写入。补结算通过已登记的 `memory.curator.receipt-repair` 宿主消息发起，不新增用户授权，和首次处理共用32请求及10分钟截止；HTTP前由宿主核对累计请求，不能因第二次SDK.run内部重新计数而赠送额外预算。仍未完成时错误明确已确认N/总数和剩余M，保留已完成结果，不再笼统显示“未更改知识”；只读查询也需真实discard终态回执，不把用户问题存成知识。

`memory_evidence` 支持query或queries（最多3个短语）定位宿主已绑定来源，返回带offset的原文片段，仍计入同一读取预算；不允许同时传定位和分页，不接任意路径/命令，也不自行做工程调查。引用只允许空白/换行、单双引号样式等价，并还原原文精确span；大小写、否定、数值、标点意义、顺序和不连续拼接不做语义近似。用户授权在绑定userText重新定位，冲突反证仍需宿主tool_output/hash/excerpt，不能用格式容错绕过。

`draftDiagnostics` 与工具schema按决策类型校验结构化字段：长期经验须有具体问题、方法、成立依据、条件、例外和未来用途，缺失返回具体字段路径；只留任务事实不强迫模型编造经验字段。Pi提示词沿用已登记的 `memory.curator.system`，同步定位、容错及错误修正方式。

限流延期仅使用宿主HTTP状态与可信响应头派生的status/retryAt；尊重Retry-After秒/日期及明确重置时间，不猜固定配额周期。支持自定义fetch的七类API在实际HTTP边界观察，不消费正文、不保存cookie/其他头，也不修改全局fetch；Google/Vertex等不支持自定义fetch的适配器保留原传输，缺少可信元数据时不从错误正文猜限流。401/403、配置/参数/CAS不盲重试；宿主预算错误按上述拆批策略恢复，未知429有界指数延期，最多三次。未来截止持久化，重启和显式重试也不会提前绕过。

UI 单独订阅 `memoryCurator:changed` 完整快照，包含工作区、会话、代次、paused/running/pending/failed、错误、可见消息和实际模型；不展示私有思考。暂停中断当前处理并保留候选，恢复才继续。清空记忆对话换代并清可见转录，不删除知识、候选或用户暂停状态；尚有待处理候选且未暂停时仍会继续整理。

知识中心的 `knowledge:list.processing` 同样透传处理器真实的 running/paused/pending/failed。`activity.todayActivations` 从本地日历零点至当前时刻按生效事件中的条目ID去重（包括恢复），不受200条动态窗口限制；24小时/7天指标仍表示操作次数，所有时间窗排除未来事件。

`knowledge:list` 保留无参数调用的完整快照行为；需要分页时传入可选查询对象 `{cursor,limit,namespace,updatedAfter,updatedBefore,maxBytes}`。`limit` 范围为1–500，默认100；`namespace` 限定 `worker`、`scheduler`、`profile` 或 `host`；更新时间范围使用 `updatedAfter`（严格晚于）和 `updatedBefore`（早于或等于）。结果按 `updatedAt` 倒序、同时间按 `id` 升序稳定排序，返回 `totalCount`、`truncated`，有后续页时返回不透明 `nextCursor`。`maxBytes` 按 UTF-8 序列化响应限制在16KiB–2MiB，默认256KiB，达到水位会在完整记录边界截断并保留续页游标；游标只由宿主生成和校验，不能手工伪造排序位置。

有界列表在 `KnowledgeStore.listPage` 中直接使用 `knowledge_hot` 的 `updated_at/id` keyset 条件、范围过滤和 `LIMIT`，IPC 只合并各命名空间返回的至多 `limit+1` 条候选；不会先把整个账本载入内存再切页。分页快照的计数和策略抑制状态由存储层摘要提供，活动列表只按最近200条事件涉及的记录做定点读取。无参数 `knowledge:list` 仍保留完整快照语义。该路径的工程回归覆盖跨页无重叠、稳定排序、时间范围过滤和 IPC 字节上限；真实大规模冷启动及 macOS/Linux 真机性能仍待发布验收。

## 执行模型发起纠错

`memory.correct({memoryId,revision,problem,evidence,suggestion?})` 面向真正执行任务的 Agent。先检索拿到 ID/revision，说明错误及本轮观察；问题和证据定位线索由模型填写，不能当作证据本身。宿主绑定当前会话、工作区、目标真实namespace/仓库/分支和原始用户/工具观察。只允许当前生产者范围或全局画像中的长期知识，拒绝任务事实、退场、已删除和过期版本。GUI与调度使用可信当前轮次；CLI沿用已认证shell调用的external memory turn包装。缺身份、无头或网络污点轮次拒绝，不接受模型伪造工作区/来源。

请求持久进入同一整理队列，返回`requestId`（候选ID）；原记忆此时不变。整理检索优先提供精确目标的当前完整结论与条件，不能被关键词排序挤掉。整理模型核对原始证据后只能`correct`、`suspend`或`discard`，暂时不可读可有限延期。更正保留ID并递增revision，完整更新结论/条件/例外；暂停退出召回；拒绝不改原记忆。不能转成save等路径、改目标、跨范围或绕过删除禁用。提交时再次检查目标CAS、处理租约、策略版本与全工作区删除对照。

工程反证必须在宿主绑定的工具观察中定位，或属于宿主确认的原始用户依据；模型自述/线索不能自证。用户原话中的明确偏好/约束更正可更新相应类型，但不能证明任意工程事实。CLI混合终端摘录本身不能通过工具反证校验，未取得可核对依据会延期或拒绝；不声称所有入口都有相同证据强度。

`memory.correctionStatus({requestId})`仅对提交会话可读，不触发模型，也不返回原始上下文。状态为pending/running/deferred/failed或updated/suspended/rejected/needs_user，带原因、原目标版本及真实结果版本（如有）。提交者在后续报告或回到任务时查询，不轮询轰炸；查询失败不能当作已经更正。相同会话、目标版本和材料幂等，跨会话不共享请求所有权；重启保留状态/回执。

`userManaged`目标仅生成持久`needs_user`提案，原条目不改变；用户在记忆中心打开原记忆后自行修订或停用。该状态表示这次审核已结束，不表示提案已应用。用户后续手工操作是独立版本操作，不自动把历史请求回执改为已应用。观察模式同样只记录未应用结果。

## 用户纠正闭环

记忆中心 `knowledge:revise` 直接发布新版本并生效，不先退出召回或另行入队。`knowledge:decide(revalidate)`立即停止使用；`knowledge:restore`恢复选定历史版本的完整内容、条件和状态，“撤销本次修改”使用同一恢复入口。删除记录也可显式修改并恢复。任务事实不可通过修订/恢复晋升成长期知识。

操作由桌面用户发起，校验当前revision、类型、重复条目和删除禁用边界；正文、状态、版本、用户依据、索引、事件与outbox同事务提交，投影落盘后返回递增版本回执。失败不冒充成功。恢复到删除状态重建墓碑，恢复有效版本移除本条墓碑。整理模型关闭、暂停、离线均不影响这些操作。

用户版本带 `userManaged` 标记。自动save/duplicate/suspend/supersede、重复候选补证据及策略补偿不能覆盖它；迟到结果仍需CAS。用户可再次修订或恢复。故障策略的旧屏蔽不再阻止用户亲自确认的新版本，恢复非生效状态不计入今日生效。后续检索使用当前有效版本；已经进入运行中模型上下文的旧文本不会凭空撤回。

记忆中心可确认已有生效条目，GUI/调度也可在本轮用户明确说出 `确认记忆 <完整ID> 正确` 后调用 `memory.confirm({id,revision})`。宿主检查原始用户消息、当前会话和版本，追加 `user_confirmed` 依据并保护新版本；模型参数、含糊确认、网络污点和无头回合不能充当用户授权。已有依据保留，不把用户确认伪称为测试或运行验证。

## 自动决策、冲突与用户删除

`KnowledgeSearch.references` 只使用词法索引和正文相似度查找当前整理范围内的比较对象、退场及删除记录。条件、例外和原始依据仍由记忆会话判断，不能以词法相似度替代结论；不再加载本地或远程向量模型。

专用Pi会话可只读比较当前工作区worker/scheduler及全局profile/host范围和各自条件，普通工作Agent仍由宿主ALS绑定原范围。比较结果按范围轮转，统一最多12条/12000序列化字符；保留完整结论、条件、例外和依据身份，省去历史版本和重复摘录。超限返回truncated/omittedRecords/notice提示收窄query，删除禁用不静默截断；提交前重新核对各范围删除记录，阻止看见同义删除后换namespace保存。用户原话支持的个人信息和偏好候选由宿主重新绑定到全局profile，其他普通候选的写入与目标CAS仍绑定原范围；host通用经验通过记忆中心由用户管理。未开放其他工作区私有知识。

`KnowledgeStore.commitCuratorDecision` 校验来源引用可逐字定位、适用范围、类型与证据、目标 revision、处理租约和政策版本。暂停或取代旧知识需要可信的原始反证且条件重叠；普通助手经验不能覆盖用户明确约束。正文/状态、关系、版本、操作回执、事件、删除禁用和 outbox 在事务中提交；Markdown 投影通过 outbox 幂等恢复，不能覆盖外部改动。

用户删除从有效知识中移除条目并保存同义禁用记录；普通候选不能恢复它。每次提交必须逐条提供本次检索返回的全部删除记录的语义比较结果，比较期间新增删除会使提交失效。只允许用户明确要求恢复，且按目标ID/revision检查，不能借改名或换类型绕过其他同义删除。语义判断仍是模型判断；这些约束保障来源、覆盖和并发一致性，不代替质量评测。

用户在记忆视图主动查询，可以读取本工作区及全局范围的历史分支知识；删除/恢复由宿主读取真实目标并重新绑定其 namespace、仓库与分支。普通工作 Agent 候选仅在画像来源验证后可写入全局profile，其他候选保持宿主绑定范围。

故障策略可通过宿主维护入口持久停用。`curatorPolicy` 按策略回执及派生关系过滤写入、core 与词法结果，包含等待异步结果期间发生的停用；有界倒序补偿经同一store的版本/outbox发布。已有用户删除不撤销，后续新证据不覆盖；不兼容的操作记为incomplete并停止使用受影响结果。分批补偿不能把尚未回退的故障前版本重新标为安全。

## 存储与历史

| 范围 | 长期条目投影 | 账本 |
|---|---|---|
| Worker共享 | `controlRoot/.muster/memory/knowledge/worker/entries/<uuid>.md` | `controlRoot/.muster/memory/knowledge/worker/ledger/knowledge.sqlite` |
| 调度专用 | `controlRoot/.muster/memory/knowledge/scheduler/entries/` | 同范围 `ledger/knowledge.sqlite` |
| 全局用户画像（含偏好） | 应用 userData 下 `memory/knowledge/entries/` | 同目录 `knowledge.sqlite` |
| 工作台通用经验 | 应用 userData 下 `memory/host-knowledge/entries/` | 同目录 `knowledge.sqlite` |

用户在记忆中心检查并编辑经验后，可复制为工作台通用经验；宿主要求当前版本仍生效、移除仓库和分支，且不会复制源证据、隐藏检索词或来源路径。该副本由用户管理，所有工作区可检索；普通候选不会自动跨项目提升，删除记录参与后续整理对照。

任务事实采用 ledger-only 存储，持久账本保存内容、依据、版本和操作关系，不生成历史Markdown投影。不再提供历史资产转换或旧格式导入；USER.md不是当前画像真源，也不自动创建第二份画像。

task_fact默认90天，到期退出查询。`curatorRetention` 只清无依赖的ledger-only正文和已完成旧source payload，保留身份/哈希/必要依据摘录；当前队列、其他namespace和全局画像库均可作为跨库租约/依赖守卫。版本、治理/curator回执、删除禁用和恢复依赖保护相关正文，旧投影与迁移备份不在此清理范围。保留回执表按单次维护批次有界写入，默认最多10,000条、约8MiB（可由宿主在64MiB内调高）；预算耗尽时提交已完成子批并返回`retention-budget`，不删除旧回执或推进未完成游标。90天前的可丢弃activity事件按单批最多500条回收；提交后尝试`wal_checkpoint(TRUNCATE)`，遇到并发读者保持WAL并继续运行，不执行阻塞式VACUUM。canonical记录、版本、治理、删除禁用、curator审计与恢复语义不因物理预算改变。

可选 `knowledge:maintenance` / `window.api.knowledge.maintenance(workspaceId,input)` 支持 `prune_history`、`stop_policy` 和 `continue_policy`。策略维护先暂停会话，逐批CAS补偿，不自动恢复故障策略；清理有25条/25毫秒的单库工作预算，并受回执条数/字节预算约束，返回blocked原因，剩余总量未知时为null。它是显式宿主维护能力，没有加入Pi工具、日常人审流程或启动迁移。

旧 `knowledgePipeline`、`knowledgeConsolidation` 和 consolidation 模型文件仍服务历史/兼容测试；旧 `knowledgeRuntime` 已删除，生产回合完成、释放、压缩、flush 的自动摄入已断开。提醒意图的触发/重置及词法检索继续保留；向量配置、模型、索引与推理依赖已移除。

## 召回与注入

常驻持续约束核心预算1200字符，用户画像核心2400字符；仅选择 active、applicability 为空且仓库/分支匹配的持续约束和画像条目。当前 `injectKnowledge` 通过 controlRoot 的 Git 身份缓存传入 core（TTL 30 秒，冷缓存或分支切换时可能暂时滞后），输出 summary、例外和 ID。常驻核心的跨分支策略尚未调整。按任务召回输出结论、完整条件、例外、依据状态与分支提示，总预算1600字符，整条放不下则跳过；方法等详情按ID查询。任务事实只有 history 查询可见，不作为普通经验常驻注入。记忆中心 `profileInjectionChars` 表示可装箱字符数，不是条目存储上限或实际送达确认；超过预算或带适用条件的画像仍可按需检索。

普通任务通过 SQLite FTS/BM25 搜索正文与 `searchKeys`，继续按 namespace、仓库、状态、期限和来源过滤，不再按分支过滤。自动召回、`memory.search` 和 `memory.list` 对存储分支与当前分支不一致的条目注明两者；当前分支不可确定时注明未知。关联结果也受同一提示和范围规则约束，最多补一跳五个节点。每次异步返回和最终格式化前重新校验当前版本、删除和策略状态。自动召回串行查询工作范围、profile和host；整体1500毫秒截止时保留已完成的工作范围命中，不取消后台查询。关键词命中不保证任意改写都可召回。

调度和Pi GUI具有逐轮核心刷新；其他GUI的核心在连接时装配，host用户回合另做任务召回。CLI任务简报带核心及召回，普通CLI后续对话没有等价逐轮刷新。普通note经整理模型识别为用户画像或偏好且通过宿主来源验证后写入全局profile，处理回执同样从profile账本恢复；明确记住继续使用memory.remember。普通memory.search(task)按宿主绑定的工作范围与全局profile/host分别检索并交错返回；history仍是工作范围历史，并附加journal预览。数据库防回流也不会自动撤回已经进入模型上下文的旧文本。

### 证据、检索与环境依赖

- `memory.note` 的工具观察初始为 `unverified`；画像写入时宿主绑定且被引用的用户原话标为 `user_stated`（用户提供），不冒充用户已经确认模型整理的条目，也不表示经过独立事实核验。明确记住或用户在记忆中心确认的依据仍标为 `user_confirmed`。未经独立验证不等于结论错误，也不会自动升级为测试或运行证据。
- `memory.search` / `memory.list` 返回有界摘要、依据等级和可见范围，按实际JSON转义后的执行器信封控制预算。search每范围最多取20个候选，`queryLimitReached` 提示还有可能存在未取出的命中；list返回当前生产者、profile与host的可见条目和范围总数，非全库盘点。`memory.get`按准确ID、版本及details/evidence分段，拼接text并解析JSON；版本变化时重新查询。专用记忆会话内的 `memory_search` 是另一接口。
- GUI和调度会话仅在上一轮已确认送达、连接及压缩状态未变、条目内容与版本完全相同时，把重复项降为ID与结论一行；失败、重连、压缩或条件变化后重新提供完整条件。调度无法读取压缩状态时不做降频。此状态不跨会话持久化。
- `memory.note` 可声明受支持的 `environmentKeys`；宿主在提交时绑定应用版本或执行器/MCP当前预算，模型不能自填值。检索与界面比较实际值，变化或不可用时提示重新核实；未声明依赖的旧记录只对已知预算变量做保守提示，不能保证识别所有旧数值。环境失配不会篡改原记忆，但不会作为无条件core注入。

## 设计初衷（2026-10-26 与用户定稿）

> 依据 campaign-intent-drafts/D10-D14.md 草案定稿（用户 2026-10-26「不抽查直接定稿」）；歧义点处置：22 项卡片决策＋长尾按草案推荐，明细见专项账本「意图定稿决策」节。

- 为谁/什么场景：跨会话长期知识（用户偏好/持续约束/可复用经验）+ 任务事实历史 + 工作日报。学习链路=工作 Agent 按需提交候选（memory.note/remember）→ 专用 Pi 记忆会话整理 → 类型化知识账本；纠错走 memory.correct 全闭环；用户在记忆中心直接修订/停用/恢复。
- 为什么这样设计：普通候选无需用户审批（低摩擦、来源可查、可撤销，审批不进自动链）；curator 独立会话五工具白名单、证据逐字定位、CAS/租约/删除禁用/策略版本复查防覆盖；宿主绑定身份防伪造工作区；回执复核补偿 ACK 丢失窗口；任务事实 ledger-only 90 天退出，重复曝光不自动晋升。
- 明确不做：旧目录自动迁移/旧格式导入已移除（软件未发布不留兼容支线）；不承诺对任意改写做语义去重；工作 Agent 未调用工具就不启动学习（无漏调自动补偿）；相似度只提供比较对象不替代结论；已进入模型上下文的旧文本不凭空撤回。
- 当前边界：core 常驻注入通过 controlRoot 的 Git 范围缓存并保留例外，普通任务召回可跨分支并附来源提示。关联 worktree 的仓库身份仍按工作树根路径识别；跨工作树共享与常驻核心是否跨分支尚未定稿。
