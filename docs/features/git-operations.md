## 操作与查询的结果独立

分支菜单的新分支名和 worktree 名输入框在响应 Enter/Escape 前检查原生 `isComposing` 与 `keyCode === 229`，输入法确认候选不触发 checkout/worktreeAdd，也不退出编辑。分支列表本身是非文本键盘导航，Enter 检出保持原合同。回归见 `test/unit/frontend-ime-actions.spec.tsx`，只模拟 IPC，不操作真实仓库。

- 暂存、提交、丢弃等本地操作失败由动作层独立记录并发到窗口顶部的红色 tip。状态读取和切换详情页不会重放已提示的错误，切仓后迟到回执按请求归属处理。
- 远端命令接受后立即记录操作种类、原始分支和开始时间。进行中的按钮显示共享 spinner，并向辅助技术播报操作状态。详情显示实际经过秒数、成功或失败、完成时间和命令摘要。
- 同仓详情实例共用 renderer 运行锁，重复点击不重发；操作状态不随内容标签隐藏而丢失。离开原仓后的晚到结果写回原仓记录，不刷新新仓。工作区或根版本变化采用不同身份。
- 后台自动 Fetch 保留用户操作回执，其他种类的成功操作也保留尚未关闭的失败回执。详情展示最近五次结果，超出这一范围的当前回执也会展示。用户可在详情中关闭当前回执，最近五次结果仍可查看。
- 远端结果先落定，再刷新本地 status。读取失败由数据层表达，不能把已成功的远端操作改判失败。
- 正常 Push 从 simple-git 的 `pushed` 与 `update` 两种结果提取实际引用和无更新标志；目标地址去掉 URL 用户名/密码和查询参数后进入摘要。运行中只展示已知的本地分支，不把 upstream 猜成实际 push 目标。

## 状态未知与旧快照

`status == null` 不等同干净。首次读取失败展示“无法确认工作区状态”和“状态未知”，不显示“工作区干净”；已成功读取过的仓保留旧文件列表并标明最后成功时间。重试成功后去掉过期提示。

状态读取错误存在时，暂存/取消暂存、提交与文件列表修改操作禁用，重试读取仍可操作。本地操作失败走 tip，远端失败同时显示详情图标的状态色和可打开的完整结果。

## 提交历史

查询当前分支历史时，Git 服务先解析 `HEAD`。有效的符号 `HEAD` 尚无提交时，主进程直接通过 `git:invokeScoped` 返回空页，历史页显示「暂无提交」。有提交时用解析出的提交 ID 查询历史。空态判定只读取引用，索引或工作区状态读取故障由对应查询单独报告。切到「所有分支」可查看其他分支的提交。损坏的引用、缺失的提交对象等历史查询失败用窗口 tip 提示。隐藏页或旧范围的迟到错误丢弃。

同一仓库和查询范围的历史页切走时保留已加载的提交、滚动位置和当前提交 Diff。切回后后台核对首页。提交前缀未变时保留已加载的后续页，并复用同一提交的文件和 Diff。

`GitHistory` 在列表内把分支图绘制在提交行的悬浮和选中底色之上。分支图可见时，指针仍能穿过图层点击对应提交行。`test/git-history-graph-visual.mjs` 用 Chromium 验证节点、跨行连线和点击。

## 丢弃范围

右键菜单按分区区分：

- 未暂存区：**丢弃未暂存改动**，调用 `discard(repo, paths, 'unstaged')`。已跟踪文件以 index 为恢复源，只改 worktree；`MM` 和新 add 后再次修改的文件保留已暂存版本。未跟踪文件按确认说明删除。
- 已暂存区：**丢弃全部改动**，调用 `discard(repo, paths, 'all')`。所列已跟踪文件恢复 HEAD 的 index/worktree；新 add 文件先取消暂存，再删除。取消暂存失败时不继续删除新文件。

**变更列表多选（2026-10-27 起）**：unstaged/staged 两棵树各自支持 Ctrl/⌘ 点选与 Shift 范围（共享 `useListSelection`，不跨分区）；修饰键点击不看 Diff，双击/右键落在多选区内时作用于整选区（目录自动展开为其全部文件路径），菜单标签带计数（如「暂存（3 项）」），多项时不提供逐项 reveal。暂存/取消暂存/丢弃沿用数组接口；分区操作完成后文件跨区流动，选区随可见行自动剪枝。回归：`test/unit/git-change-tree-multiselect.spec.tsx`。

确认框显示冻结的仓路径、文件列表、影响区域、新文件删除数与不可撤销说明；切换到另一个仓后旧确认不能用于新仓。原有省略 mode 的调用保持全部丢弃语义，生产详情始终显式传范围。后端拒绝无效范围和越界相对路径；传给 Git restore 的路径统一使用 `:(literal)`，特殊文件名不会扩大确认范围。

此操作没有新增内容备份或撤销承诺；批量操作仍可能部分完成后返回具体错误。确认期间其他进程修改文件的精确内容版本保护尚未实现。

## 分支与 Stash 恢复

菜单使用“临时保存”表达 Stash，与 Stage 暂存区分开。stash push 后记录恢复用 OID。切换后恢复时既处理命令异常，也读取实际 `conflicted` 文件：simple-git 对 stash pop 冲突可能 resolve，不能只依赖 catch。

部分完成返回 `warning:true`、消息、恢复 OID 和可取得的冲突文件。菜单保留警告并刷新父面板真实状态；状态刷新在请求入口及响应返回时核对当前仓与工作区身份，切仓后旧回调不会取消新请求或发布旧仓快照；父面板独立保留该提示，关闭菜单不会抹掉它。切换失败后的自动恢复若再次失败，同样携带警告，不忽略二次错误。所有结束路径失效 HEAD/status 缓存，包括已切分支但恢复失败的路径。

本轮提供记录与冲突信息，没有新增完整 Stash 管理器或通用冲突解决器。

## 远端更新检查

- “刷新本地状态”只读取本地状态；“检查远端（Fetch）”显式执行 Git Fetch。
- 推送和拉取按钮显示当前上游的待推和待拉数量，零用低强调样式。无上游或状态未知时，按钮的提示和可访问描述说明原因。详情图标提示尚未检查、刚刚检查、距上次成功的分钟数或检查失败，弹窗可查看检查时间与原始原因。
- 主进程检查记录按仓库以及分支/upstream 归属。Fetch 成功才更新 `checkedAt`；失败记录错误和本次尝试时间，保留同身份的上次成功时间。普通 status 不更新检查时间。
- 当前显示且窗口聚焦的仓库，在就绪一秒后检查，之后最短两分钟一次；页面隐藏/失焦停止发起，回到前台按尝试时间节流，同仓多实例共用锁。无 upstream 不自动检查，仍可手动 Fetch；不对仓库列表所有成员批量联网。
- 手动操作、自动检查都会刷新当前仓状态，更新待推/待拉数量；进入后台后完成的命令保留记录，重新激活时按原数据层读取状态。

检查时间和操作记录是本次进程/renderer 内存事实，不跨应用重启持久化；外部终端 Fetch 不会伪造一次本应用成功检查。Git 远端配置被外部替换后，旧检查记录的配置身份细化仍属后续工作。

## 设计初衷（2026-10-26 与用户定稿）

> 依据 campaign-intent-drafts/D08-D00.md 草案定稿（用户 2026-10-26「不抽查直接定稿」）；歧义点处置：22 项卡片决策＋长尾按草案推荐，明细见专项账本「意图定稿决策」节。

- 仓库详情支持暂存、提交、按分区丢弃和远端同步。远端反馈覆盖待推与待拉数量、检查新鲜度、运行中操作及回执。本地防护包括丢弃确认、Stash 临时保存与恢复警告。
- 为什么这样设计：操作错误与查询错误独立（状态读成功不清掉操作失败，切仓不把 A 仓错误显示给 B 仓）；`status==null` ≠ 干净——首次失败显式「无法确认工作区状态」，读过的保留旧列表+最后成功时间（不伪装）；丢弃按分区区分 unstaged/all 且确认框冻结仓路径+文件列表+影响区域+新文件删除数（切仓旧确认不通用；`:(literal)` 防特殊文件名扩大范围）；远端命令接受即记录、同仓运行锁防重发、晚到结果写回原仓不刷新新仓；Fetch 成功才更新 checkedAt（普通 status 不伪造新鲜度）、失败保留上次成功时间；聚焦仓就绪 1s 后检查、最短 2 分钟节流、失焦停止（不对全仓列表批量联网）。
- 明确不做：丢弃没有备份/撤销承诺（Git restore 语义）；确认期间其他进程修改文件的精确内容版本保护未实现；检查时间与操作记录是本进程/renderer 内存事实、不跨重启持久化，外部终端 Fetch 不会伪造本应用成功检查；无完整 Stash 管理器或通用冲突解决器（只提供恢复 OID+冲突文件信息）。
- 歧义点：丢弃（discard）零备份——A=接受 Git restore 语义（确认框已给足冻结信息与不可撤销说明；review 对误操作防护只审确认框质量与范围正确性，不把「无撤销」当缺陷）／B=未来做丢弃备份（如先入 stash 或临时快照再 restore，配回收入口）。推荐 A——B 改变 Git 命令语义、引入额外失败面（stash 本身可能冲突）；若用户曾真实误丢改动再升 B。
